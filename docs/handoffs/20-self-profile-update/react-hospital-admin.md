# 병원 자기 프로필 수정 React 병원·관리자 웹 핸드오프

```text
Feature: 20-self-profile-update
Backend Feature: docs/features/20-self-profile-update/
Related PR: NONE
Available After: MAIN_MERGE
Breaking Change: NO
Hospital Impact: YES
Admin Impact: NONE
```

## 변경 요약

- 새로 가능해진 병원 동작: 자기 응급실 기본주소·상세주소·좌표·연락처를 함께 수정할 수 있습니다.
- 새로 가능해진 관리자 동작: 없음. 슈퍼 관리자는 이 API를 사용할 수 없습니다.
- 기존 웹 영향: 기존 `GET /api/v1/hospitals/me`와 수신 상태 변경 API는 유지되고 같은 자기 프로필 경로의 `PUT`만 추가됩니다.
- 정보 수정은 `receivingStatus`를 변경하지 않습니다.
- 수정 전에 생성된 병원 제안은 당시 위치·연락처를 유지하고, 수정 후 새로 생성되는 제안부터 최신 프로필을 사용합니다.

## 역할별 사용자 흐름

| 역할 | 순서 | 사용자·웹 동작 | API 호출 | 성공 후 상태 |
|---|---:|---|---|---|
| 병원 관계자 | 1 | 설정 화면 진입 | `GET /api/v1/hospitals/me` | 서버의 최신 병원 정보·수신 상태 표시 |
| 병원 관계자 | 2 | 주소 검색·상세주소·지도 위치·연락처 편집 | 호출 없음 | 로컬 입력값만 변경 |
| 병원 관계자 | 3 | 저장 | `PUT /api/v1/hospitals/me` | HTTP 200 전체 프로필로 화면 갱신 |
| 슈퍼 관리자 | - | 병원 정보 대리 수정 | 지원하지 않음 | 기존 관리자 기능만 유지 |

## 인증과 접근 범위

| 역할 | 인증 | 허용 작업 | 조직·정보 접근 범위 |
|---|---|---|---|
| 병원 관계자 | Bearer Access Token | 자기 병원 프로필 조회·수정 | JWT 계정·병원 조직에 연결된 병원 프로필 한 건 |
| 슈퍼 관리자 | Bearer Access Token | 없음 | 병원 공용 계정 프로필 수정 불가 |

- 역할은 활성 `HOSPITAL_STAFF`여야 합니다.
- 병원·계정·조직 ID를 Path, Query 또는 요청 본문으로 보내지 않습니다.
- 서버가 JWT와 현재 DB 계정·조직·프로필을 다시 대조합니다.

## API 1. 자기 병원 프로필 조회

### `GET /api/v1/hospitals/me`

- 목적: 설정 화면과 새로고침 뒤 서버의 최신 병원 정보·수신 상태 복구
- 인증·역할: Bearer Access Token, `HOSPITAL_STAFF`
- 조직·정보 접근 범위: 자기 병원 프로필 한 건
- 성공 HTTP: `200 OK`
- 요청 본문: 없음

#### 성공 응답

```json
{
  "accountId": "ACCOUNT_UUID",
  "loginId": "hospital01",
  "role": "HOSPITAL_STAFF",
  "organizationId": "ORGANIZATION_UUID",
  "organizationName": "한성대학교병원",
  "hospitalId": "HOSPITAL_UUID",
  "address": "서울특별시 성북구 삼선교로 16길",
  "detailAddress": "본관 1층 응급의료센터",
  "latitude": 37.5821000,
  "longitude": 127.0105000,
  "contact": "02-1234-5678",
  "receivingStatus": "ON",
  "updatedAt": "2026-08-18T10:00:00Z"
}
```

## API 2. 자기 병원 프로필 수정

### `PUT /api/v1/hospitals/me`

- 목적: 응급실 위치와 연락처 전체 수정
- 인증·역할: Bearer Access Token, `HOSPITAL_STAFF`
- 조직·정보 접근 범위: 자기 병원 프로필 한 건
- 성공 HTTP: `200 OK`
- Content-Type: `application/json`
- `Idempotency-Key`: 필요 없음

#### 요청

```json
{
  "address": "서울특별시 성북구 삼선교로 16길",
  "detailAddress": "본관 1층 응급의료센터",
  "latitude": 37.5821000,
  "longitude": 127.0105000,
  "contact": "02-1234-5678"
}
```

| 필드 | 타입 | 필수 | Nullable | 제약 |
|---|---|---:|---:|---|
| `address` | string | O | X | 앞뒤 공백 제거 후 1~255자 |
| `detailAddress` | string | X | O | 앞뒤 공백 제거 후 최대 200자, `null` 또는 공백은 저장된 상세주소 제거 |
| `latitude` | number | O | X | -90 이상 90 이하 |
| `longitude` | number | O | X | -180 이상 180 이하 |
| `contact` | string | O | X | 앞뒤 공백 제거, 8~30자, 첫 글자는 숫자 또는 `+`, 이후 숫자·`-`만 허용 |

- 다섯 필드를 한 요청으로 전송합니다. 일부 필드만 보내는 부분 수정은 지원하지 않습니다.
- 주소를 선택한 뒤 지도에서 확인한 위도·경도를 함께 보내야 합니다.
- 백엔드는 이번 API에서 Geocoding을 호출하거나 주소·좌표의 실제 일치 여부를 판정하지 않습니다.
- 요청에 `receivingStatus`를 넣지 않습니다. 수신 상태는 기존 별도 API로만 변경합니다.

#### 성공 응답

- `GET /api/v1/hospitals/me`와 같은 전체 병원 프로필을 반환합니다.
- `address`, `detailAddress`, 좌표와 `contact`는 정규화·저장된 값입니다.
- 계정·조직·병원 공개 ID와 `receivingStatus`는 기존 값을 유지합니다.
- `updatedAt`은 프로필 변경 서버 시각으로 갱신됩니다.
- 웹은 요청값을 그대로 확정하지 말고 HTTP 200 응답 전체를 화면 상태로 사용합니다.

#### 오류

| 오류 코드 | HTTP | 발생 조건 | 웹에서 필요한 처리 |
|---|---:|---|---|
| `COMMON_001` | 400 | 필수값 누락, 주소·상세주소 길이, 좌표 범위, 연락처 형식 오류 | 입력 항목을 수정하고 전체 요청 재전송 |
| `AUTH_001` | 401 | Access Token 없음 | 로그인 화면 이동 |
| `AUTH_002` | 401 | 만료·위조 토큰 또는 비활성 계정 | 토큰 갱신 1회, 실패하면 로그인 |
| `AUTH_003` | 403 | 병원 관계자 역할이 아님 | 병원 설정 접근 차단 |
| `COMMON_004` | 403 | 토큰·계정·조직·프로필 연결 불일치 | 인증정보 제거 후 운영 담당자 확인 |
| `HOSPITAL_001` | 404 | 자기 병원 프로필 없음 | 운영 담당자 확인 |

- 실패하면 위치·연락처 어느 것도 저장되지 않고 수신 상태도 바뀌지 않습니다.

## 기존 병원 제안 적용 시점

| 대상 | 위치·연락처 |
|---|---|
| 수정 전에 이미 생성된 병원 제안 | 제안 생성 당시 주소·상세주소·좌표·연락처 유지 |
| 수정 후 새로 생성되는 병원 제안 | 수정된 최신 병원 프로필 사용 |

- 진행 중 이송 카드의 목적지 정보를 바꾸기 위한 API가 아닙니다.
- 기존 수락·거절·철회·인계 이력은 수정하지 않습니다.

## 화면 상태 조건

| 대상 | 조건 | 웹에서 필요한 처리 |
|---|---|---|
| 최초 설정 화면 | `GET` 처리 중 | 브라우저의 이전 값 대신 로딩 상태 표시 |
| 저장 버튼 | 모든 필수 필드와 지도 좌표 확인 완료 | 전체 `PUT` 요청 허용 |
| 저장 성공 | HTTP 200 | 전체 응답으로 입력값·수신 상태·변경 시각 갱신 |
| 저장 실패 | 표준 오류 응답 | 서버 기준 기존 프로필을 유지하고 필요 시 `GET` 재조회 |
| 수신 상태 | 프로필 수정 전후 | 기존 `ON` 또는 `OFF` 유지 |

## 오류 처리

공통 오류 응답:

```json
{
  "code": "COMMON_001",
  "message": "요청값 검증에 실패했습니다.",
  "fieldErrors": [],
  "traceId": "TRACE_ID"
}
```

- 오류 문의 시 API 경로, HTTP 상태, `code`, `traceId`를 전달합니다.
- Access·Refresh Token, 실제 연락처와 정확한 좌표는 메신저·노션·로그에 공유하지 않습니다.

## 실시간 이벤트와 재조회

- 이벤트: 없음
- 재연결 후 재조회 API: `GET /api/v1/hospitals/me`
- 중복 클릭·멱등성 계약: 같은 전체 `PUT` 재전송은 프로필·병원 제안 중복을 만들지 않습니다.
- 프로필 수정은 기존 병원 요청 SSE를 발생시키지 않습니다.
