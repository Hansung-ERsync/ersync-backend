```text
Feature: eight-character-invitation-code
Backend Feature: docs/features/14-eight-character-invitation-code/
Related PR: NONE
Available After: MAIN_MERGE
Breaking Change: NO
```

> 새로 발급되는 가입 코드는 8자리지만, 배포 전에 발급된 긴 코드도 만료·사용
> 전까지 계속 가입에 사용할 수 있는 전환 계약입니다.

## 변경 요약

- 가입 코드 사전 확인과 구급대원 회원가입 API 경로·요청·응답은 변경되지 않았습니다.
- 새로 발급되는 코드는 정확히 `[A-Za-z0-9_-]{8}`입니다.
- 기존에 발급된 약 43자리 코드도 백엔드에서 계속 검증합니다.
- 가입 코드는 대소문자를 구분합니다.
- Refresh Token은 기존 약 43자리이며 이번 변경 대상이 아닙니다.

## 사용자 흐름

| 순서 | 앱 동작 | API | 결과 |
|---:|---|---|---|
| 1 | 전달받은 가입 코드 원문 입력 | 화면 입력 | 대소문자와 `-`, `_` 유지 |
| 2 | 소속·역할 사전 확인 | `POST /api/v1/auth/invitations/validate` | 조직·`PARAMEDIC` 역할·필수 동의 확인, 코드 미소비 |
| 3 | 같은 원문으로 회원가입 제출 | `POST /api/v1/auth/signups/paramedic` | 성공 시 코드가 `USED`로 1회 소비 |

## 입력 규칙

- 신규 코드: `[A-Za-z0-9_-]{8}`
- legacy 코드: 배포 전에 발급된 약 43자리 Base64 URL 문자열
- 전환 기간에는 입력창을 정확히 8자로만 제한하지 않습니다.
- 입력값을 자동으로 대문자나 소문자로 변환하지 않습니다.
- `-`, `_`를 제거하거나 다른 기호로 바꾸지 않습니다.
- 서버는 앞뒤 공백을 제거하지만 앱도 제출 전 앞뒤 공백을 정리할 수 있습니다.
- 코드 내부에 공백을 삽입하지 않습니다.
- 가입 코드 원문을 로그·분석 이벤트·오류 문의에 남기지 않습니다.

## API 1. 가입 코드 사전 확인

### `POST /api/v1/auth/invitations/validate`

```json
{
  "invitationCode": "Ab12_-Z9"
}
```

- 성공: `200 OK`
- 성공 응답의 조직·역할·필수 동의 계약은 기존과 같습니다.
- 사전 확인 성공은 코드를 소비하지 않습니다.
- 응답에는 가입 코드 원문이나 digest가 포함되지 않습니다.

## API 2. 구급대원 회원가입

### `POST /api/v1/auth/signups/paramedic`

- 기존 회원가입 요청의 `invitationCode`에 사전 확인한 원문을 그대로 넣습니다.
- 신규 8자리와 아직 유효한 기존 긴 코드 모두 사용할 수 있습니다.
- 회원가입 성공만 코드를 `USED`로 전환합니다.
- 연락처·동의·이름·로그인 ID·비밀번호 계약은 변경하지 않았습니다.

## 오류 처리

| 코드 | HTTP | 조건 | 앱 처리 |
|---|---:|---|---|
| `INVITATION_001` | 400 | 존재하지 않음, 오타, 대소문자 변경 | 원문 재확인 |
| `INVITATION_002` | 409 | 만료 | 관리자에게 새 코드 요청 |
| `INVITATION_003` | 409 | 이미 회원가입에 사용 | 새 코드 요청 또는 기존 계정 로그인 |
| `INVITATION_004` | 409 | 관리자가 폐기 | 관리자에게 새 코드 요청 |
| `COMMON_001` | 400 | 빈 입력 등 형식 오류 | 입력 확인 |
