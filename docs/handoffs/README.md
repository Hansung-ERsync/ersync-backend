# 프론트엔드 핸드오프

백엔드 기능을 구현하고 검증한 뒤 프론트 작업자가 바로 연동할 수 있는 문서를
대상별로 전달합니다. 핸드오프는 API 스키마뿐 아니라 사용자 동작, 권한, 상태,
오류와 재조회 조건을 포함합니다.

프론트 작업자는 전체 제품을 이해할 때 `docs/agents/context.md`와
`docs/agents/frontend.md`를 먼저 읽습니다. 기능 연동 시에는 해당 대상의
핸드오프를 추가로 읽습니다.

## 구조

```text
docs/handoffs/{번호}-{기능명}/
  flutter-paramedic.md
  react-hospital-admin.md
```

영향이 있는 파일만 생성합니다.

| 영향 대상 | 생성 파일 |
|---|---|
| Flutter 구급대원 앱 | `flutter-paramedic.md` |
| React 병원·관리자 웹 | `react-hospital-admin.md` |
| 양쪽 모두 | 두 파일 모두 |
| 프론트 영향 없음 | 생성하지 않고 기능 review에 `NONE` 기록 |

## 생성 기준

다음 중 하나라도 변경되면 해당 대상의 핸드오프를 작성합니다.

- API Method, Path, 요청 또는 응답
- 인증, 역할 또는 조직 접근 범위
- 상태, Enum 또는 화면 노출 조건
- 오류 코드, 재시도 또는 중복 요청 처리
- 실시간 이벤트와 재연결 후 재조회 조건

## 작성 규칙

- 구현과 로컬 검증을 마친 실제 코드와 테스트를 기준으로 작성합니다.
- 해당 프론트 작업자가 다른 백엔드 문서를 읽지 않아도 되게 작성합니다.
- 예정 기능, 추천 설계와 미결정 사항을 포함하지 않습니다.
- 기능에서 실제로 사용하는 필드, Enum과 오류를 문서에 직접 기록합니다.
- 프론트 상태관리, 폴더 구조, 라이브러리와 컴포넌트 구현을 지시하지 않습니다.
- 두 문서가 같은 API를 사용하면 같은 PR의 코드와 테스트를 기준으로 일치시킵니다.
- dev API는 `main` 병합과 배포 성공 후 사용할 수 있습니다.

템플릿은 `docs/templates/handoff/`를 사용합니다.
