## 목적

- 구급대원이 여러 수락 병원 중 현재 목적지 한 곳을 직접 선택·변경합니다.
- 목적지가 아닌 수락·응답 대기 병원도 허용된 응답을 계속할 수 있습니다.
- 목적지 병원이 긴급 철회하면 같은 이송 요청으로 현재 위치 재검색을 시작합니다.
- 병원별 응답·목적지 변경·철회 이력을 삭제하지 않습니다.

## 정책 기준

### 목적지 선택과 변경

- 여러 병원이 `ACCEPTED`일 수 있지만 현재 목적지는 최대 한 곳입니다.
- 수락만으로 목적지를 자동 확정하지 않습니다.
- 구급대원이 수락 병원 중 한 곳을 직접 선택합니다.
- 목적지를 A에서 B로 변경하면 B가 현재 목적지가 되고 A의 수락은 유지됩니다.
- A에는 `다른 병원으로 이동 중`, B에는 `우리 병원으로 이동 중`을 표시합니다.
- 철회되지 않은 A는 이후 다시 목적지로 선택할 수 있습니다.

### 목적지가 아닌 병원

- 수락·미선택 병원은 `수락 완료 · 다른 병원으로 이동 중`으로 유지합니다.
- `PENDING` 병원은 `다른 병원으로 이동 중 · 응답 가능`으로 유지합니다.
- 수락·미선택 병원은 수락을 철회할 수 있습니다.
- `PENDING` 병원은 계속 수락하거나 거절할 수 있습니다.
- 두 병원 모두 목적지 선택 이후의 임상 갱신과 정확한 위치는 받지 않습니다.
- `PENDING` 병원이 늦게 수락해도 목적지는 자동으로 변경되지 않습니다.

### 병원 수락 철회

- 목적지 선택 전 또는 다른 목적지가 유지되는 수락·미선택 병원은 일반 수락 철회를 사용합니다.
- 현재 목적지 병원은 일반 철회 대신 `수용 불가 긴급 고지`를 사용합니다.
- `HANDOFF_REQUESTED` 이후에는 앱에서 철회할 수 없습니다.
- 철회 사유는 다음 중 하나가 필수입니다.

```text
BED_SHORTAGE
OPERATING_ROOM_SHORTAGE
SPECIALIST_UNAVAILABLE
EQUIPMENT_UNAVAILABLE
OTHER
```

- `OTHER`는 공백이 아닌 상세 사유가 필요합니다.
- 철회한 병원은 해당 이송 요청에서 다시 수락하거나 목적지로 선택할 수 없습니다.

### 목적지 병원의 긴급 철회

현재 목적지 A병원이 긴급 철회하면 다음을 한 트랜잭션 흐름으로 처리합니다.

1. A의 제안을 `ACCEPTANCE_WITHDRAWN`으로 변경하고 목적지에서 해제합니다.
2. A를 해당 이송 요청의 이후 후보에서 제외합니다.
3. 구급대원에게 사유를 포함한 긴급 갱신 신호를 보냅니다.
4. 같은 `TransportRequest`, 임상·응답·목적지 이력을 유지합니다.
5. 구급대원의 최신 위치를 기준으로 새 검색 회차를 시작합니다.
6. 다른 수락 병원은 그대로 유지해 즉시 목적지로 선택할 수 있게 합니다.
7. 기존 `PENDING` 병원은 새 카드를 만들지 않고 기존 카드를 `재요청`으로 갱신해 다시 알립니다.
8. 재요청 병원에는 그 시점의 최신 최소 환자정보를 제공합니다.
9. 기존 `REJECTED` 병원에는 다시 요청하지 않습니다.
10. 현재 위치에서 새로 발견한 적격 병원에만 새 제안을 만듭니다.
11. 새 수락이 발생해도 목적지는 구급대원이 직접 선택합니다.

구급대원 화면에는 별도 `수락 병원 없음` 상태를 만들지 않고 `새로운 목적지를 찾고 있습니다`를 표시합니다. 내부 상태 표현은 구현 계획에서 정하되 후보 소진 정책을 다시 도입하지 않습니다.

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 목적지 선택 뒤 다른 병원 | 수락·응답 대기 카드를 유지 | 늦은 수락과 수동 목적지 변경을 계속 허용 |
| 구급대원의 목적지 변경 | 이전 목적지의 수락 유지 | 필요하면 다시 선택할 수 있게 함 |

| 재요청 대상 | `PENDING` 재알림, 신규 병원 추가, `REJECTED` 제외 | 중복 카드와 반복 거절 요청을 방지 |
| 다음 목적지 | 구급대원이 직접 선택 | 시스템이 의료·이송 결정을 자동화하지 않음 |
