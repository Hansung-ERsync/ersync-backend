# 구급대원 이송 상세 복구 요구사항

```text
Feature: transport-request-detail-recovery
Owner: backend
Related Issue: NONE
Frontend Impact: FLUTTER_PARAMEDIC
Policy Decision Status: NONE
```

> Flutter 앱 재실행·인증 복구 후 진행 중 이송 화면을 서버의 확정 데이터로
> 다시 구성하기 위한 구급대원 본인용 이송 상세 조회 기능입니다. 기존 임상
> timeline·병원 탐색·위치 조회 계약은 유지하고, 현재 빠진 최초 환자·발생
> 정보와 최신 임상 요약을 한 응답으로 제공합니다.

## 목적

- 앱이 재실행되거나 메모리의 진행 중 환자정보를 잃어도 서버 데이터로 이송 화면을 복구합니다.
- 나이·성별·주증상 등 최초 입력값과 최신 Pre-KTAS·의식·활력징후·처치를 함께 조회합니다.
- 요청 ID만 안다고 다른 구급대원의 환자정보를 조회하지 못하도록 계정·조직·소유권을 서버에서 검증합니다.
- 기존 조회 API의 역할을 유지하고 정확한 위치·연락처 등 불필요한 민감정보를 새 응답에 추가하지 않습니다.

## 이번 기능 범위

### 포함

- `GET /api/v1/transport-requests/{requestId}` 구급대원 이송 상세 조회 API
- 진행 중인 자기 이송 요청의 상태·프로토콜 버전·생성 시각 조회
- 최초 환자 기본정보 조회
  - 나이 상태, 나이 값, 성별
- 최초 발생·증상정보 조회
  - 발생 유형·상세, 손상 기전·부위, 주증상·상세, 부증상, 증상 발생 시각 상태·시각
- 현재 환자 snapshot 조회
  - 최신 Pre-KTAS, 의식 상태, 활력징후, 현재 처치 목록, 마지막 임상 갱신 시각
- 앱 재실행과 Access Token 갱신 뒤 `ACTIVE` 목록에서 얻은 요청 ID로 상세를 복구하는 계약
- 역할·활성 계정·조직·요청 소유권 테스트
- Flutter 구급대원 앱 핸드오프

### 제외

- 환자 기본정보·발생정보 수정 API
- 기존 활력징후·의식·Pre-KTAS·처치 추가 API 변경
- 전체 임상 원본 이력 반환
- 병원 후보·응답·목적지·거리·ETA 반환
- 구급차의 최초 위치·최신 위치·전체 이동경로 반환
- 구급대원 회신 연락처 반환
- 완료·취소 이력 상세 화면 추가
- 병원 관계자·슈퍼 관리자용 이송 상세 API
- DB 스키마와 기존 이송 데이터 변경

## 정책 기준

- 적용할 MVP 요구사항:
  - 구급대원은 개인 계정으로 자신이 생성한 이송 요청만 조회합니다.
  - 이송 중 새 평가는 기존 기록을 덮어쓰지 않고 추가하며, 화면 복구에는 서버의 현재 snapshot을 사용합니다.
  - 환자 이름, 주민등록번호, 연락처, 정확한 생년월일과 상세 주소는 수집·반환하지 않습니다.
  - 측정·관찰·처치 시각, 앱 입력 시각과 서버 수신 시각을 구분합니다.
  - 프론트의 메모리 상태나 SSE 이벤트가 아니라 REST와 DB의 확정 상태를 복구 기준으로 사용합니다.
- 기존 정책과 충돌: 없음

### 상세 조회 대상

- 활성 `PARAMEDIC` 계정이 자신의 Access Token으로 요청합니다.
- JWT의 계정·조직·역할과 DB의 현재 활성 상태를 확인합니다.
- URL의 `requestId`가 인증 계정이 직접 생성한 요청인지 서버에서 검증합니다.
- 같은 구급대 조직의 다른 구급대원이 만든 요청도 조회할 수 없습니다.
- 앱 화면 복구 대상은 기존 `ACTIVE` 목록에 포함되는 다음 상태입니다.

```text
SEARCHING
CANDIDATES_EXHAUSTED
ACCEPTED_AVAILABLE
EN_ROUTE
HANDOFF_REQUESTED
```

- `COMPLETED`, `CANCELLED` 요청은 기존 `HISTORY`·`RECENT` 목록의 최소 종료 이력을 사용하며 이번 상세 API로 환자정보를 제공하지 않습니다.
- `ACTIVE` 목록 조회 뒤 상세 조회 전에 요청이 종료된 경우 상세 조회는 찾을 수 없는 요청으로 처리하고 앱은 `ACTIVE`·`RECENT` 목록을 다시 조회합니다.

### 반환할 환자·발생정보

- 환자 기본정보는 최초 요청에 저장된 `ageStatus`, `ageYears`, `sex`를 반환합니다.
- 발생정보는 최초 요청에 저장된 다음 값을 반환합니다.
  - `occurrenceType`, 조건부 `occurrenceDetail`
  - 조건부 `injuryMechanism`, `injurySites`
  - `primarySymptom`, 조건부 `primarySymptomDetail`, `secondarySymptoms`
  - `onsetTimeStatus`, 조건부 `onsetAt`
- 최초 환자·발생정보는 이송 중 갱신 대상이 아니므로 생성 당시 값을 유지합니다.
- 이름·주민등록번호·환자 연락처·정확한 생년월일·상세 주소는 응답에 포함하지 않습니다.

### 반환할 최신 임상 snapshot

- `latestSnapshot`은 요청의 `CurrentPatientSnapshot`이 가리키는 현재 값을 반환합니다.
- 포함 항목은 기존 임상 timeline의 `latestSnapshot`과 같은 의미를 사용합니다.
  - 최신 Pre-KTAS와 평가 시각·기준 버전
  - 최신 AVPU 의식 상태와 관찰 시각
  - 최신 다섯 활력징후와 측정 시각
  - 현재 처치 목록
  - `lastClinicalUpdateAt`
- 이송 중 새 임상 기록이 추가되면 다음 상세 조회는 갱신된 snapshot을 반환합니다.
- 늦게 도착한 과거 임상 기록은 원본 timeline에는 추가되지만 현재 snapshot을 전진시키지 않았다면 상세 응답도 과거 값으로 되돌아가지 않습니다.
- 전체 원본 이력이 필요한 화면은 기존
  `GET /api/v1/transport-requests/{requestId}/clinical-timeline`을 사용합니다.

### 기존 복구 API와의 관계

- 앱은 로그인·토큰 갱신 뒤 다음 순서로 서버 상태를 복구합니다.
  1. `GET /api/v1/transport-requests?view=ACTIVE`로 진행 중 요청 ID와 상태를 확인합니다.
  2. 새 상세 API로 최초 환자·발생정보와 최신 임상 snapshot을 복구합니다.
  3. 기존 병원 탐색 API로 병원 후보·응답·목적지·ETA를 복구합니다.
  4. 기존 위치 API로 마지막 위치와 최신 여부를 복구합니다.
  5. SSE를 다시 연결하고 이후 변경 신호를 받으면 관련 REST API를 재조회합니다.
- 새 상세 응답은 병원 탐색·위치 응답을 합치지 않습니다. 각 데이터의 권한과 갱신 주기가 다르고 기존 API가 이미 서버 권위 복구 계약을 제공하기 때문입니다.
- 조회 API이므로 `Idempotency-Key`는 사용하지 않으며 조회 자체가 상태·이력·감사·알림을 변경하지 않습니다.

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 진행 중 자기 이송 상세 조회 | `GET /api/v1/transport-requests/{requestId}`에 Access Token을 보내 요청 상태·프로토콜 버전·최초 환자·발생정보·최신 임상 snapshot·서버 시각을 받음 |
| 앱 재실행 복구 | `ACTIVE` 목록의 요청 ID를 기준으로 상세·병원 탐색·위치 API를 재조회한 뒤 SSE를 재연결함 |
| 이송 중 임상 갱신 후 재조회 | 기존 임상 추가 API가 snapshot을 갱신한 뒤 상세 API가 최신 snapshot을 반환함 |
| 전체 임상 이력 조회 | 새 상세 API가 아니라 기존 `clinical-timeline` 페이지 API를 사용함 |

## 기존 API 호환성

- 새 `GET /api/v1/transport-requests/{requestId}`만 추가하며 기존 요청·응답 필드를 삭제하거나 의미를 바꾸지 않습니다.
- 기존 `GET /api/v1/transport-requests?view=ACTIVE|RECENT|HISTORY` 목록 계약은 유지합니다.
- 기존 임상 갱신·timeline, 병원 탐색, 위치, SSE 계약은 유지합니다.
- 병원 제안 상세 DTO를 구급대원에게 그대로 노출하지 않고 구급대원 소유권에 맞는 별도 응답을 사용합니다.

## 완료 조건

- [ ] 앱이 재실행된 뒤 `ACTIVE` 요청 ID로 최초 환자·발생정보와 최신 임상 snapshot을 복구함
- [ ] 나이·성별·주증상·발생정보와 최신 Pre-KTAS·의식·활력징후·처치가 실제 저장 데이터와 일치함
- [ ] 늦은 과거 임상 기록이 상세의 최신값을 되돌리지 않고, 최신 임상 갱신은 다음 상세 조회에 반영됨
- [ ] 다른 구급대원·조직·역할·미인증·비활성 계정의 접근을 차단함
- [ ] 완료·취소된 요청은 상세 환자정보를 반환하지 않고 목록 재조회로 복구할 수 있음
- [ ] 응답에 정확한 위치, 전체 이동경로, 구급대원 연락처, 토큰과 내부 DB ID가 포함되지 않음
- [ ] 기존 목록·임상 timeline·병원 탐색·위치·SSE API 계약과 테스트가 유지됨
- [ ] DB migration 없이 현재 저장 구조로 조회하며 MySQL 통합·권한·상태 경합 테스트를 통과함
- [ ] Flutter 핸드오프가 앱 재실행 복구 순서와 실제 응답 필드를 독립적으로 설명함
