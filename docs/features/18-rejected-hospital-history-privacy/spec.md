# 거절 병원 이력 개인정보 보호 요구사항

```text
Feature: 18-rejected-hospital-history-privacy
Owner: Backend
Related Issue: NONE
Frontend Impact: REACT_HOSPITAL_ADMIN
Policy Decision Status: RESOLVED
```

## 목적

- 요청을 거절한 병원의 환자 임상정보 접근을 즉시 종료합니다.
- HISTORY에는 병원 자신의 거절 결과와 처리 시각만 남깁니다.

## 정책 기준

- 적용할 MVP 요구사항: 병원에는 수용 판단에 필요한 정보만 제공하며 거절·철회·종료 병원에는 환자정보를 추가 제공하지 않습니다.
- 기존 정책과 충돌: 기능 17의 거절 시점 고정 snapshot 조회 계약을 기능 12의 종료 이력 최소화 계약으로 대체합니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 병원이 요청을 거절하고 HISTORY를 조회 | 상태·거절 사유·상세·처리 시각만 표시하고 환자정보는 숨김 |
| 2 | 거절한 제안의 상세·임상 이력·위치를 조회 | 모두 `404 TRANSPORT_005` |
| 3 | 거절 후 환자 임상정보가 갱신되거나 이송이 종료 | 거절 병원에 새 정보가 노출되지 않고 최소 이력만 유지 |
| 4 | 병원이 활성 `PENDING`·`ACCEPTED` 제안을 조회 | 기존 허용 범위와 응답 동작 유지 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| HISTORY 목록 | 기존 200·페이징 유지, `rejectionReason`·`rejectionDetail` 추가, 임상·연락처·거리·ETA 제거 |
| 종료 제안 상세 | `GET /api/v1/hospitals/me/offers/{offerId}`를 `404 TRANSPORT_005`로 차단 |
| 임상 이력·위치 | 기존 종료 제안 차단 계약 유지 |
| 활성 목록·상세 | 변경 없음 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `HOSPITAL_STAFF` | 자기 병원 HISTORY 결과 조회 | 공개 ID, 상태, 자기 응답 사유와 처리 시각만 |
| `PARAMEDIC` | 변경 없음 | 자기 이송 요청 범위 |
| `SUPER_ADMIN` | 없음 | 병원 제안·환자 임상·위치 접근 금지 |

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 종료 제안 상세·임상 이력·위치 조회 | `TRANSPORT_005` | 404 |
| 다른 병원 조직의 제안 조회 | `TRANSPORT_005` | 404 |
| 병원 역할·조직 검증 실패 | 기존 인증·권한 오류 | 401 또는 403 |

## 완료 조건

- [ ] 모든 HISTORY 항목이 최소 목록 DTO로 반환됨
- [ ] 거절 사유·상세와 처리 시각은 HISTORY 목록에 유지됨
- [ ] 거절·철회·레거시 무응답·완료·취소 제안의 상세 조회가 차단됨
- [ ] 임상·연락처·거리·ETA가 종료 이력에 노출되지 않음
- [ ] 활성 제안과 다른 조직·역할의 기존 계약이 회귀하지 않음
- [ ] React 핸드오프와 통합 리뷰가 현재 계약으로 갱신됨

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 거절 뒤 환자정보 유지 여부 | 즉시 상세 접근 차단 | 거절하면 수용 판단 목적이 종료됨 |
| HISTORY 표시 정보 | 식별자·상태·거절 사유·처리 시각만 유지 | 병원의 처리 이력은 보존하고 환자정보는 최소화 |
| 기존 200 상세 계약 | `404 TRANSPORT_005`로 변경 | React가 거절 카드의 상세 링크를 제거해야 함 |
