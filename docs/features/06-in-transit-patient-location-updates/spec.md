# 이송 중 환자·위치 갱신 요구사항

```text
Feature: in-transit-patient-location-updates
Owner: backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: NONE
```

> 구급대원이 활성 이송 요청에 새 임상 기록과 최신 구급차 위치를 추가하고,
> 현재 수용 판단 권한이 있는 병원만 최신 임상정보를, 현재 목적지 병원만 정확한
> 위치와 동적 ETA를 확인하는 기능입니다. 임상 이력은 덮어쓰지 않고 보존하며
> GPS 전체 이동 경로는 저장하지 않습니다.

## 목적

- 이송 중 변하는 환자 상태를 기존 기록을 보존하면서 빠르게 추가합니다.
- 병원 카드에는 가장 최근 임상 요약을, 권한 있는 상세 화면에는 시간순 이력을 제공합니다.
- 현재 목적지 병원이 구급차의 최신 위치, 마지막 수신 시각, 거리와 예상 ETA를 확인합니다.
- 위치 전송이 끊겨도 마지막 위치를 유지하고 30초 이후에는 오류가 아닌 `STALE` 상태로 표시합니다.
- 목적지 변경·철회·재탐색 중에도 임상정보와 정확한 위치의 노출 범위가 서버에서 즉시 바뀌게 합니다.

## 이번 기능 범위

### 포함

- 새 활력징후 5종 세트 추가
- 새 의식 상태 평가 추가
- 같은 요청의 평가 프로토콜을 사용하는 Pre-KTAS 재평가 추가
- 새 처치 또는 실패한 처치 시도 추가
- 임상 원본 이력 보존과 최신 환자 snapshot 갱신
- 구급대원 최신 위치 갱신과 요청별 단일 최신 위치 유지
- 현재 목적지까지 거리·ETA 비동기 재계산
- 최신 위치의 `CURRENT`·`STALE` 상태와 마지막 수신 경과시간 조회
- 목적지 철회 재탐색의 최신 위치 사용
- 대상 병원별 임상정보·정확한 위치 접근 제어
- 임상·위치 갱신의 멱등성, 동시성 제어, 감사와 최소 SSE 신호
- Flutter 구급대원 앱과 React 병원 웹 연동 계약

### 제외

- 환자 이름, 주민등록번호, 생년월일, 환자 연락처와 상세 주소
- 최초 환자·발생 정보 자체의 수정·삭제
- GPS 전체 이동 경로와 위치별 ETA 이력 저장
- 백그라운드 위치 권한을 포함한 Flutter 플랫폼 설정
- 지도 화면, 마커 이동과 폴리라인 렌더링 구현
- 상황실 협조, 의료지도와 병원 외 제3자 위치 공유
- 이송 취소, 인계 완료 요청과 병원 인계 확인
- 공식 Pre-KTAS 규칙 변경과 새 평가 프로토콜 배포

## 정책 기준

### 갱신 가능한 요청 상태

- 요청을 생성한 활성 `PARAMEDIC` 계정만 자기 조직·자기 요청을 갱신할 수 있습니다.
- 임상 갱신은 `SEARCHING`, `CANDIDATES_EXHAUSTED`, `ACCEPTED_AVAILABLE`, `EN_ROUTE`에서 허용합니다.
- 위치 갱신도 같은 활성 상태에서 허용합니다. 목적지 철회 후 이동 중인 구급차의 최신 좌표를 재탐색 기준으로 사용하기 위해 `SEARCHING`에서도 저장합니다.
- `HANDOFF_REQUESTED`, `COMPLETED`, `CANCELLED`에서는 새 임상·위치 갱신을 거절합니다.
- 계정 또는 구급대 조직이 비활성이면 갱신할 수 없습니다.

### 임상 기록 추가

- 이송 중 추가할 수 있는 기록은 활력징후, 의식 상태, Pre-KTAS와 처치입니다.
- 새 기록은 기존 행을 수정하거나 삭제하지 않고 append-only로 저장합니다.
- 활력징후는 혈압·맥박·호흡수·체온·산소포화도 다섯 항목 모두 값 또는 공식 상태를 가져야 합니다.
- 의식·Pre-KTAS·처치는 최초 요청과 같은 조건부 검증 규칙을 사용합니다.
- 평가 프로토콜 버전은 요청 생성 시 고정된 버전을 서버가 사용하며 클라이언트가 갱신할 수 없습니다.
- 각 기록은 측정·관찰·평가·처치 시각, 앱 입력 시각과 서버 수신 시각을 구분해 저장합니다.
- 네트워크 지연으로 오래된 관찰 기록이 나중에 도착해도 이력에는 추가하지만, 현재 snapshot은 임상 발생 시각이 가장 최신인 기록을 가리킵니다.
- 같은 임상 시각이면 서버 수신 순서를 사용해 최신 snapshot을 결정합니다.
- 잘못 입력한 이전 기록을 직접 수정하지 않습니다. 올바른 새 평가를 추가하고 이전 값은 이력에 남깁니다.
- 최신 snapshot 변경과 병원 알림 의도 저장은 같은 트랜잭션에서 처리합니다.

### 임상정보 노출 대상

- 목적지 선택 전에는 `PENDING` 병원과 아직 목적지가 없는 `ACCEPTED` 병원이 최신 임상 요약을 조회할 수 있습니다.
- 목적지 선택 후에는 현재 목적지 병원만 이후 최신 임상 요약과 전체 임상 이력을 조회할 수 있습니다.
- 목적지가 변경되면 이전 목적지 병원의 이후 임상 갱신 접근을 즉시 종료하고 새 목적지 병원에 현재 snapshot과 이력을 제공합니다.
- 거절·무응답·철회 병원, 비목적지 수락 병원과 종료된 요청의 병원 활성 화면에는 이후 임상정보를 제공하지 않습니다.
- 병원 계정은 구급대원이 기록한 임상정보를 추가·수정·삭제할 수 없습니다.
- `SUPER_ADMIN`은 임상정보를 조회하거나 갱신할 수 없습니다.

### 최신 위치 저장

- Flutter 앱은 이송 중 약 10초 간격으로 현재 위치를 전송합니다. 서버는 정확히 10초인지 강제하지 않습니다.
- 위치 입력에는 위도, 경도와 단말이 위치를 획득한 `capturedAt`이 필요합니다.
- 서버는 별도의 `lastReceivedAt`을 기록합니다.
- 위도는 -90~90, 경도는 -180~180 범위만 허용합니다.
- 요청별 최신 위치 한 건만 유지하고 이전 정확한 좌표는 저장하지 않습니다.
- 새 위치가 현재 저장 위치보다 오래된 `capturedAt`이면 성공적으로 수신하되 최신 좌표를 되돌리지 않습니다.
- 같은 시각의 위치가 도착하면 서버 수신 순서가 나중인 값을 최신 위치로 사용합니다.
- 정확한 좌표는 애플리케이션 로그, 오류 응답, 감사 payload와 SSE payload에 기록하지 않습니다.
- 위치 갱신 행위는 계정·조직·요청·서버 시각만 감사하며 좌표 원문을 남기지 않습니다.

### 위치 조회와 오래된 상태

- 정확한 최신 위치는 현재 목적지 병원과 요청 소유 구급대원만 조회할 수 있습니다.
- 목적지가 없는 병원, 이전 목적지, 비목적지 수락 병원과 `SUPER_ADMIN`에는 정확한 위치를 제공하지 않습니다.
- 서버가 `lastReceivedAt`부터 30초 미만이면 `CURRENT`, 30초 이상이면 `STALE`을 반환합니다.
- 조회 응답에는 `capturedAt`, `lastReceivedAt`, `serverNow`, 서버가 계산한 `ageSeconds`와 상태를 포함합니다.
- `STALE`이어도 마지막 위치를 반환하여 병원이 지도에서 마지막 좌표와 `마지막 수신 N초/분 전`을 함께 표시할 수 있게 합니다.
- 새 위치가 저장되면 별도 복구 명령 없이 자동으로 `CURRENT`로 돌아옵니다.
- 위치 미수신과 `STALE`은 오류나 긴급 알림이 아니며 경고음 이벤트를 만들지 않습니다.

### 거리·ETA와 재탐색

- 현재 목적지가 있으면 위치 갱신 뒤 최신 위치에서 목적지 병원까지 거리·ETA 재계산을 비동기로 예약합니다.
- 빠르게 여러 위치가 도착하면 아직 처리되지 않은 계산은 최신 위치 기준으로 합쳐 외부 지도 API 호출을 제한합니다.
- ETA 상태는 기존 `CALCULATING`, `AVAILABLE`, `UNAVAILABLE` 계약을 유지하고 계산 시각을 함께 반환합니다.
- 지도 API 실패는 위치·임상 갱신 성공을 되돌리지 않습니다.
- 마지막 성공 ETA가 있으면 계산 시각과 함께 유지할 수 있으며 현재 계산 실패 상태를 함께 표시합니다.
- 현재 목적지가 없으면 동적 ETA를 계산하지 않지만 최신 위치는 저장합니다.
- 현재 목적지 철회로 재탐색할 때 `SearchOriginResolver`는 요청 생성 좌표보다 최신 저장 위치를 우선 사용합니다.

### 멱등성·동시성·실시간 갱신

- 모든 임상 추가와 위치 갱신에는 `Idempotency-Key`가 필수입니다.
- 키는 기존 계약과 동일한 8~100자의 영문·숫자 및 `._:-`만 허용합니다.
- 같은 키와 같은 payload를 재전송하면 최초 결과를 반환하고 기록·snapshot·알림·감사를 중복 생성하지 않습니다.
- 같은 키로 다른 payload를 제출하면 `COMMON_005`로 거절합니다.
- 서로 다른 임상 갱신이 동시에 도착해도 모든 원본을 보존하고 최신 snapshot을 결정적으로 계산합니다.
- 위치 갱신과 목적지 변경·철회가 동시에 실행되면 요청을 기준으로 직렬화하고 최종 현재 목적지만 정확한 위치와 ETA를 조회합니다.
- 임상 갱신에는 `VITAL_SIGNS_ADDED`, `CONSCIOUSNESS_CHANGED`, `PRE_KTAS_CHANGED`, `TREATMENT_ADDED`, `PATIENT_SNAPSHOT_UPDATED` 중 필요한 최소 SSE 신호를 보냅니다.
- 위치·ETA에는 `AMBULANCE_LOCATION_UPDATED`, 기존 `ETA_UPDATED` 신호를 보냅니다.
- SSE에는 임상정보와 정확한 좌표를 넣지 않으며, 클라이언트는 이벤트 수신 후 권한 있는 REST API를 다시 조회합니다.

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 활력징후 추가 | 자기 요청에 다섯 항목과 측정·입력 시각을 추가하고 새 기록 ID, snapshot 갱신 여부와 서버 수신 시각 반환 |
| 의식 상태 추가 | AVPU 또는 평가 불가 사유와 관찰·입력 시각을 추가하고 새 기록과 최신 snapshot 상태 반환 |
| Pre-KTAS 재평가 | 완료 단계 또는 긴급 미완료 사유와 평가·입력 시각을 추가하고 요청에 고정된 프로토콜로 기록 |
| 처치 추가 | 처치 종류·결과·조건부 상세·시행·입력 시각을 추가하고 실패한 시도도 이력에 보존 |
| 구급대원 임상 이력 조회 | 자기 요청의 임상 원본을 시간순으로 조회하고 현재 snapshot을 함께 반환 |
| 병원 임상 이력 조회 | 현재 접근 권한이 있는 자기 병원 제안에 한해 최신 snapshot과 시간순 기록 반환 |
| 최신 위치 갱신 | 자기 요청의 위도·경도·획득 시각을 받아 최신 위치 교체 여부, 수신 시각과 freshness 반환 |
| 목적지 병원 위치 조회 | 현재 목적지인 자기 병원 제안에 한해 최신 좌표·freshness·경과시간·거리·ETA 반환 |
| 실시간 갱신 | 기존 인증 SSE에 임상 snapshot·위치·ETA 변경 신호를 추가하고 대상별 REST 재조회 |

> 구체적인 API path와 DTO는 위 동작을 분리된 명령·조회 계약으로 구현하고
> `implementation.md`에서 현재 패키지와 기존 API 호환성을 기준으로 확정합니다.

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `PARAMEDIC` | 임상 기록 추가·이력 조회, 최신 위치 갱신·조회 | 자기 계정과 자기 구급대 조직이 생성한 활성 이송 요청만 |
| `HOSPITAL_STAFF` | 최신 임상 요약·허용된 이력 조회, 현재 위치·ETA 조회 | 임상은 현재 공개 대상인 자기 병원 제안, 정확한 위치는 현재 목적지 제안만 |
| `SUPER_ADMIN` | 없음 | 환자 임상정보·정확한 위치와 관련 명령·조회 금지 |
