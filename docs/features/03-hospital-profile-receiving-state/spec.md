# 병원 프로필·응급실 수신 상태 요구사항

```text
Feature: hospital-profile-receiving-state
Domain: hospital
Owner: backend
Related Issue: NONE
Frontend Impact: YES
```

> 병원 공용 계정이 자기 병원의 응급실 프로필을 등록·조회하고 새 요청 수신
> 상태를 ON/OFF로 관리하는 흐름입니다.

## 목적

- 병원 조직은 응급실 주소, 확인된 위도·경도, 연락처를 병원 프로필로 저장합니다.
- 병원 프로필의 수신 상태는 최초 `OFF`로 시작합니다.
- 병원 공용 계정은 자기 병원 수신 상태만 `ON` 또는 `OFF`로 변경합니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 병원 계정이 자기 병원 프로필을 등록함 | 주소·좌표·연락처가 저장되고 수신 상태는 `OFF` |
| 2 | 병원 계정이 자기 병원 프로필을 조회함 | 저장된 프로필과 현재 수신 상태를 확인 |
| 3 | 병원 계정이 수신 상태를 `ON`으로 변경함 | 이후 병원 탐색 후보로 사용할 수 있는 상태가 됨 |
| 4 | 구급대원 또는 다른 병원이 상태를 변경함 | 권한 오류가 반환됨 |
| 5 | 병원 조직이 아닌 조직이 프로필을 만들려고 함 | 병원 프로필 생성이 거부됨 |

## API

| 행위 | Method·Path | 요청·응답 핵심 |
|---|---|---|
| 내 병원 프로필 등록·수정 | `PUT /api/v1/hospital/profile` | erAddress/latitude/longitude/erContact |
| 내 병원 프로필 조회 | `GET /api/v1/hospital/profile` | 프로필과 receivingStatus |
| 수신 상태 변경 | `PUT /api/v1/hospital/receiving-status` | status `ON` 또는 `OFF` |

프론트엔드 영향이 `YES`이므로 구현과 검증 후
`docs/contracts/03-hospital-profile-receiving-state.md`를 작성합니다.

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `HOSPITAL_STAFF` | 자기 병원 프로필 등록·조회, 수신 상태 변경 | 본인 조직 |
| `SUPER_ADMIN` | 없음 | 이번 기능에서는 병원 프로필을 직접 수정하지 않음 |
| `PARAMEDIC` | 없음 | 접근 불가 |

## 오류

| 조건 | 오류 코드 | HTTP |
|---|---|---:|
| 요청값 검증 실패 | `COMMON_001` | 400 |
| 인증 없음·토큰 오류 | `AUTH_001` 또는 `AUTH_002` | 401 |
| 병원 계정 권한 없음 | `AUTH_003` | 403 |
| 병원 프로필 없음 | `HOSPITAL_001` | 404 |
| 병원 조직이 아님 | `HOSPITAL_002` | 409 |
| 수신 상태 변경 불가 | `HOSPITAL_003` | 409 |

## 확정 정책

| 쟁점 | 최종 결정 | 결정 이유·영향 |
|---|---|---|
| 프로필 등록 시점 | 병원 가입 후 병원 계정이 `PUT /api/v1/hospital/profile`로 등록 | 직전 가입 기능에 병원 상세 정보가 없으므로 독립 검수 가능한 흐름으로 분리 |
