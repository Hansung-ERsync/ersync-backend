## 목적

- 구급대원이 병원을 직접 고르지 않아도 현재 위치에서 적격 응급실을 찾습니다.
- 첫 수락 전까지 반경을 확대하고 새로 포함된 병원에만 요청합니다.
- 병원은 요청을 수락하거나 필수 사유와 함께 거절합니다.
- 병원별 요청 카드를 한 이송 건에서 하나만 유지합니다.

## 정책 기준

- 최초 반경은 10km, 최소 후보 수는 3곳입니다.
- 후보가 부족하면 10km씩 즉시 확대하고 최대 검색 반경은 100km입니다.
- 첫 전송 이후 수락이 없으면 60초마다 10km씩 확대합니다.
- 첫 수락이 발생하면 자동 반경 확대를 중단합니다.
- 여러 병원이 수락할 수 있으며 수락만으로 목적지가 결정되지 않습니다.
- 수락이나 거절을 누르지 않은 병원은 계속 `PENDING`, 화면상 `응답 대기`입니다.
- 새 이송 요청에는 별도의 `NO_RESPONSE` 결과를 만들지 않습니다.
- MVP에서는 최소 한 병원이 최종적으로 수락한다고 가정합니다.
- `CANDIDATES_EXHAUSTED`, 최대 반경 이후 전체 재전송과 병원 전화 연결은 MVP에서 사용하지 않습니다.
- 목적지 병원의 긴급 철회로 발생하는 현재 위치 재검색은 기능 05 정책을 따릅니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 10km 1곳, 20km 2곳, 30km 4곳 | 30km의 적격 병원 4곳에 최초 요청 |
| 2 | 첫 전송 뒤 60초 동안 수락 없음 | 반경을 10km 확대하고 새 병원에만 요청 |
| 3 | A병원이 수락 | 자동 확대 중단, A를 수락 목록에 추가하되 목적지는 미선택 |
| 4 | A 수락 뒤 B도 수락 | 두 수락을 유지하고 구급대원이 목적지를 직접 선택 |
| 5 | C병원이 수락·거절하지 않음 | C는 별도 무응답 전이 없이 계속 응답 대기 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 이송 요청 생성 | 현재 위치 기준 최초 병원 탐색과 병원별 제안 생성 |
| 검색 현황 조회 | 반경, 병원별 `PENDING`·`ACCEPTED`·`REJECTED`, 거절 사유 반환 |
| 병원 수락 | 제안을 `ACCEPTED`로 변경하고 첫 수락이면 자동 확대 중단 |
| 병원 거절 | 제안을 `REJECTED`로 변경하고 필수 사유 저장 |
| 전체 재전송·전화 연결 | MVP 공개 동작으로 제공하지 않음 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `PARAMEDIC` | 자기 요청의 탐색·응답 현황 조회 | 자신이 생성한 요청만 |
| `HOSPITAL_STAFF` | 수락·거절, 자기 병원 제안 조회 | JWT의 병원 조직에 전달된 제안만 |
| `SUPER_ADMIN` | 없음 | 환자 임상·위치·병원 응답 접근 금지 |

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 인증 없음·유효하지 않은 토큰 | `AUTH_001` 또는 `AUTH_002` | 401 |
| 역할·조직 또는 요청 소유권 위반 | `AUTH_003`, `COMMON_004` 또는 존재 비노출 404 | 403/404 |
| 잘못된 거절 사유 또는 `OTHER` 상세 누락 | `COMMON_001` | 400 |
| 이미 확정된 제안에 다른 응답 | `TRANSPORT_006` | 409 |
| 같은 요청과 병원에 중복 제안 생성 시도 | 기존 제안을 반환하거나 충돌 없이 갱신 | 200 |

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 응답하지 않은 병원 | 계속 `PENDING`으로 유지 | 무응답과 응답 대기를 중복 상태로 관리하지 않음 |
| 검색 실패 처리 | 최소 한 병원이 수락한다고 가정 | 후보 소진·전체 재전송·전화 연결은 MVP 범위에서 제외 |
| 병원별 중복 요청 | 요청당 병원 카드 하나 | 재알림이 환자 수와 카드 수를 증가시키지 않게 함 |
