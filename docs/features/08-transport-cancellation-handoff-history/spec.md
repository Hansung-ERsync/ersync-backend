# 이송 취소·인계 완료 및 이력 요구사항

```text
Feature: transport-cancellation-handoff-history
Owner: backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: NONE
```

> 구급대원이 인계 완료 요청 전까지 사유와 함께 이송을 취소하거나, 실제
> 목적지 병원 도착 후 인계 완료를 요청하고 목적지 병원이 인수를 확인해 이송을
> 종료하는 기능입니다. 완료·취소된 요청은 활성 화면에서 제거하되 응답·목적지·
> 임상 갱신과 종료 이력을 삭제하지 않습니다.

## 목적

- 더 이상 이송하지 않는 요청을 필수 사유와 함께 안전하게 취소합니다.
- 구급대원의 완료 요청과 현재 목적지 병원의 확인이 모두 있어야 이송을 완료합니다.
- 취소·인계 명령이 동시에 실행되거나 재시도돼도 요청이 모순된 종료 상태가 되지 않게 합니다.
- Flutter 메인 화면에서 본인의 활성 이송과 최근 완료·취소 이력을 복구할 수 있게 합니다.
- 병원 활성 목록에서 종료 요청을 제거하고 자기 병원 응답 이력은 유지합니다.

## 이번 기능 범위

### 포함

- 요청 소유 구급대원의 필수 사유가 있는 이송 취소
- 취소 시 현재 목적지 해제와 진행 중 탐색·제안 종료
- 취소 영향을 받는 병원에 최소 실시간 갱신 신호 전달
- 요청 소유 구급대원의 인계 완료 요청
- 현재 목적지 병원 공용 계정의 환자 인계 확인
- `HANDOFF_REQUESTED`, `COMPLETED`, `CANCELLED` 상태 전이와 종료 시각·행위자 이력
- 병원 제안 활성 목록 제거와 기존 응답·목적지·임상 이력 보존
- 구급대원 본인의 활성 요청 및 최근 완료·취소 이력 목록
- 병원 기존 `ACTIVE`·`HISTORY` 목록의 인계 대기·완료·취소 상태 반영
- 취소·인계 명령의 멱등성, 동시성 제어, 감사와 최소 SSE 신호
- Flutter 구급대원 앱과 React 병원 웹 연동 계약

### 제외

- 취소된 요청 재개와 기존 요청 복사 생성
- `HANDOFF_REQUESTED` 철회, 취소 또는 이전 상태 복구
- 완료된 요청 취소·재개·수정
- 환자 인계 수령자의 개인 이름·서명·직원별 계정
- 병원 밖 제3자의 인계 확인
- 전체 감사 로그 검색·다운로드와 관리자 이력 화면
- 법정 보존기간 확정, 자동 삭제와 비식별화 배치
- 최근 이송 목록에서 환자 임상정보·정확한 위치를 재노출하는 기능

## 정책 기준

### 이송 취소

- 요청을 생성한 활성 `PARAMEDIC` 계정만 자기 조직·자기 요청을 취소할 수 있습니다.
- 취소는 `SEARCHING`, `CANDIDATES_EXHAUSTED`, `ACCEPTED_AVAILABLE`, `EN_ROUTE`에서 허용합니다.
- `HANDOFF_REQUESTED`, `COMPLETED`, `CANCELLED`에서는 취소할 수 없습니다.
- 취소 사유는 다음 중 하나가 필수입니다.

```text
PATIENT_REFUSED_TRANSPORT
GUARDIAN_SELF_TRANSPORT
SCENE_RESOLVED
OTHER
```

- `OTHER`에는 공백이 아닌 200자 이하의 상세 사유가 필요하고, 다른 사유에는 상세를 보내지 않습니다.
- 취소는 요청 상태를 `CANCELLED`로 변경하고 행위 계정·구급대 조직·사유·서버 시각을 보존합니다.
- 현재 목적지가 있으면 활성 목적지에서 해제하지만 이전 목적지 선택 이력은 삭제하지 않습니다.
- 진행 중인 자동 탐색·철회 복구 탐색과 ETA 작업은 더 이상 새 병원 제안이나 갱신을 만들지 않게 종료합니다.
- `PENDING`·`ACCEPTED` 제안은 취소 시각에 닫되 기존 응답 상태·사유·시각을 다른 상태로 덮어쓰지 않습니다.
- 취소 영향을 받는 모든 `PENDING`·`ACCEPTED` 병원에는 현재 활성 목록을 재조회할 수 있는 최소 신호를 전달합니다. 선택 후 숨겨진 수락 병원도 포함합니다.
- 취소된 요청은 재개하지 않으며 다시 이송해야 하면 새 요청을 생성합니다.

### 인계 완료 요청

- 요청 소유 구급대원만 `EN_ROUTE` 요청의 인계 완료를 요청할 수 있습니다.
- 인계 완료 요청에는 철회되지 않은 현재 목적지 `ACCEPTED` 제안이 반드시 있어야 합니다.
- 요청이 성공하면 상태를 `HANDOFF_REQUESTED`로 변경하고 요청 계정·구급대 조직·서버 시각을 기록합니다.
- 현재 목적지는 유지하며 목적지 병원 활성 카드에는 인계 확인이 필요한 상태를 표시합니다.
- `HANDOFF_REQUESTED`부터 새 임상·위치 갱신, 목적지 변경, 병원 수락 철회와 이송 취소를 허용하지 않습니다.
- 현재 목적지 병원에는 환자정보를 넣지 않은 최소 인계 요청 신호를 보내고, 병원은 REST API를 재조회합니다.
- 구급대원 한쪽의 요청만으로는 이송이 완료되지 않습니다.

### 병원 인계 확인과 완료

- `HANDOFF_REQUESTED` 상태에서 현재 목적지 병원 조직의 활성 `HOSPITAL_STAFF` 공용 계정만 인계를 확인할 수 있습니다.
- 목적지가 아닌 병원, 이전 목적지와 다른 병원 조직은 인계 요청 존재 여부와 환자정보를 확인하거나 완료할 수 없습니다.
- 병원 확인이 성공하면 요청을 `COMPLETED`로 변경하고 확인 계정·병원 조직·서버 시각을 기록합니다.
- 완료 후 최종 목적지 연결과 목적지 선택 이력은 보존하지만 활성 목적지로 취급하지 않습니다.
- 모든 병원 제안을 완료 시각에 닫고 Flutter 활성 이송과 병원 `ACTIVE` 목록에서 제거합니다.
- 구급대원과 영향을 받는 병원에는 완료 상태 재조회를 위한 최소 신호를 전달합니다.
- 완료된 요청에는 취소, 목적지 변경, 재탐색, 병원 응답·철회, 임상·위치 갱신과 추가 인계 명령을 허용하지 않습니다.

### 활성·최근 이송 이력

- 구급대원은 자기 계정으로 생성한 요청만 목록으로 조회합니다. 같은 구급대 조직의 다른 대원 요청은 조회할 수 없습니다.
- `ACTIVE` 목록은 `SEARCHING`, `CANDIDATES_EXHAUSTED`, `ACCEPTED_AVAILABLE`, `EN_ROUTE`, `HANDOFF_REQUESTED` 요청을 반환합니다.
- `HISTORY` 목록은 `COMPLETED`, `CANCELLED` 요청을 종료 시각 최신순으로 반환합니다.
- Flutter 홈의 `RECENT` 목록은 `HANDOFF_REQUESTED`, `COMPLETED`, `CANCELLED`를 상태 변경 시각 최신순으로 한 번에 반환합니다.
- 목록은 페이지 기반으로 조회하며 기본 크기는 20, 최대 크기는 100으로 제한합니다.
- 각 항목에는 요청 공개 ID, 상태, 생성 시각, 마지막 상태 변경 시각과 현재 또는 마지막 목적지 병원명 요약을 포함합니다.
- 완료 항목에는 완료 시각과 최종 목적지 병원명을 포함합니다.
- 취소 항목에는 취소 시각·취소 사유와 취소 전에 선택한 마지막 목적지 병원명이 있으면 이력용으로 포함합니다. 목적지가 없었던 취소는 병원명을 `null`로 반환합니다.
- 최근 목록에는 환자 임상정보, 구급대원 연락처, 정확한 좌표, 토큰과 내부 DB ID를 포함하지 않습니다.
- 병원은 기존 자기 제안 `ACTIVE`·`HISTORY` 목록만 사용합니다. `HANDOFF_REQUESTED`인 현재 목적지 제안은 확인 전까지 `ACTIVE`, `COMPLETED`·`CANCELLED` 요청의 자기 제안은 `HISTORY`로 조회합니다.
- 병원 이력에서는 자기 제안의 응답 상태와 요청 종료 상태·시각만 제공하고 종료 후 임상정보·연락처·정확한 위치를 다시 제공하지 않습니다.

### 멱등성·동시성·감사

- 이송 취소, 인계 완료 요청과 병원 인계 확인에는 `Idempotency-Key`가 필수입니다.
- 키는 기존 계약과 동일한 8~100자의 영문·숫자 및 `._:-`만 허용합니다.
- 같은 키와 같은 명령을 재시도하면 최초 결과를 반환하고 상태·이력·감사·알림을 중복 생성하지 않습니다.
- 같은 키로 다른 payload 또는 다른 의미의 명령을 보내면 `COMMON_005`로 거절합니다.
- 명령은 이송 요청을 기준으로 직렬화하고 상태 전이, 종료 이력, 감사와 outbox 저장을 한 트랜잭션에서 처리합니다.
- 취소와 병원 수락·목적지 선택이 경합하면 먼저 확정된 명령 뒤 다음 명령이 최신 상태를 다시 검증합니다. 취소가 확정된 뒤에는 다른 상태 변경이 성공하지 않습니다.
- 인계 완료 요청과 목적지 병원 철회가 경합하면 먼저 확정된 명령만 유효합니다. 인계 요청이 먼저면 철회가 실패하고, 철회가 먼저면 목적지가 해제되어 인계 요청이 실패합니다.
- 병원 인계 확인과 중복 취소·변경 명령이 경합해도 최종 상태는 `COMPLETED` 또는 선행 유효 상태 하나만 유지합니다.
- 감사에는 `TRANSPORT_CANCELLED`, `HANDOFF_REQUESTED`, `HANDOFF_CONFIRMED` 행위와 서버 시각·행위자·조직을 기록합니다.
- SSE에는 취소 상세 사유, 임상정보, 연락처와 정확한 위치를 넣지 않습니다.

|---:|---|---|
| 1 | 병원 탐색 중 환자가 이송을 거부해 구급대원이 취소 | 요청이 `CANCELLED`가 되고 탐색·제안이 닫히며 병원 활성 카드에서 제거; 사유와 기존 임상·응답 이력은 유지되고 재개 불가 |

| 3 | 인계 완료 요청과 A병원의 수락 철회가 거의 동시에 도착 | 요청 잠금으로 직렬화; 인계 요청이 먼저면 철회 실패, 철회가 먼저면 목적지가 해제되어 인계 요청 실패, 모순된 완료·철회 동시 상태 없음 |
| 4 | 취소·인계 명령 성공 응답을 받지 못해 같은 키로 재시도 | 최초 결과를 그대로 반환하고 종료 이력·감사·SSE가 한 번만 생성됨 |
| 5 | 앱을 다시 연 구급대원이 최근 이송 목록 조회 | 본인의 활성 요청과 `COMPLETED`·`CANCELLED` 이력을 최신순으로 복구하며 다른 대원의 요청과 환자 임상정보·좌표는 노출되지 않음 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 이송 취소 | 자기 요청에 `Idempotency-Key`, 취소 사유와 선택적 `OTHER` 상세를 제출하고 `CANCELLED`, 취소 시각과 사유 반환 |
| 인계 완료 요청 | 자기 `EN_ROUTE` 요청에 `Idempotency-Key`를 제출하고 `HANDOFF_REQUESTED`, 현재 목적지와 요청 시각 반환 |
| 병원 인계 확인 | 현재 목적지 병원이 자기 제안에 `Idempotency-Key`를 제출하고 `COMPLETED`, 완료 시각 반환 |
| 구급대원 이송 목록 | 본인 요청을 `ACTIVE`, `HISTORY` 또는 Flutter 홈용 `RECENT`로 페이지 조회하고 상태·시각·목적지 최소 요약 반환 |
| 병원 활성·이력 목록 | 기존 자기 제안 조회에서 `HANDOFF_REQUESTED`는 현재 목적지 활성 카드로 유지하고 `COMPLETED`·`CANCELLED`는 최소 이력으로 이동 |
| 실시간 갱신 | 기존 인증 SSE에 취소·인계 요청·완료 최소 신호를 추가하고 이벤트 수신 후 대상별 REST API 재조회 |

> 구체적인 API path와 DTO는 현재 Controller 구조와 기존 계약을 기준으로
> `implementation.md`에서 확정합니다.

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `PARAMEDIC` | 자기 이송 취소, 인계 완료 요청, 활성·최근 이송 목록 조회 | 자기 계정과 자기 구급대 조직이 생성한 요청만 |
| `HOSPITAL_STAFF` | 인계 요청 확인·완료, 자기 제안 활성·이력 조회 | `HANDOFF_REQUESTED`인 현재 목적지와 자기 병원 조직의 제안만 |
| `SUPER_ADMIN` | 없음 | 환자 임상정보·위치·취소·인계·이송 이력 접근 금지 |

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 인증 없음·유효하지 않은 Access Token | `AUTH_001` 또는 `AUTH_002` | 401 |
| 역할·활성 계정·조직 조건 불일치 | `AUTH_003`, `COMMON_004` 또는 `USER_002` | 403 |
| 없거나 다른 구급대원 소유의 요청 | `TRANSPORT_001` | 404 |
| 다른 병원 조직, 비목적지 또는 존재하지 않는 제안 | `TRANSPORT_005` | 404 |
| 취소·인계 요청·확인이 허용되지 않는 요청 상태 | `TRANSPORT_004` | 409 |
| 현재 목적지가 없거나 현재 목적지 제안이 더 이상 `ACCEPTED`가 아님 | `TRANSPORT_004` | 409 |
| 취소 사유·`OTHER` 상세·페이지·멱등성 키 형식 오류 | `COMMON_001` | 400 |
