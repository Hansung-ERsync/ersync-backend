# 병원·구급대원 자기 프로필 수정 요구사항

```text
Feature: 20-self-profile-update
Owner: Backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

## 목적

- 병원 공용 계정이 가입 때 등록한 응급실 위치와 응급실 연락처를 직접 최신화할 수 있게 합니다.
- 구급대원이 자기 이름과 병원 회신용 연락처를 직접 최신화할 수 있게 합니다.
- 수정된 현재 프로필과 이미 생성된 이송 요청·병원 제안의 당시 기록을 분리해 진행 중·과거 이력의 의미가 바뀌지 않게 합니다.

## 정책 기준

- 적용할 MVP 요구사항:
  - 병원 프로필은 응급실 기본주소·선택 상세주소·지도에서 확인한 위도·경도·응급실 연락처를 보관합니다.
  - 병원은 응급실 단위 공용 계정 1개를 사용하고, 구급대원은 개인별 계정을 사용합니다.
  - 구급대원의 연락처는 병원이 이송 요청에 회신할 때 사용하는 연락처입니다.
  - 역할·조직 단위 접근 제어를 적용하고 연락처·정확한 위치를 로그에 남기지 않습니다.
  - 병원 제안의 병원 위치·연락처와 이송 요청의 구급대원 회신 연락처는 생성 당시 값으로 보존합니다.
- 기존 병원 가입·자기 프로필 조회·수신 상태 변경과 구급대원 가입·자기 프로필 조회 계약을 유지합니다.
- 기존 정책과 충돌: 없음

## 수정 범위

| 대상 | 수정 가능 필드 | 수정하지 않는 필드 |
|---|---|---|
| 병원 | `address`, `detailAddress`, `latitude`, `longitude`, `contact` | 계정·로그인 ID·역할·조직·병원 ID·수신 상태 |
| 구급대원 | `displayName`, `callbackContact` | 계정·로그인 ID·역할·소속 조직·동의 이력 |

- 병원 위치는 기본주소·상세주소·위도·경도를 한 요청으로 함께 제출합니다.
- 병원 `detailAddress`만 선택값이며 `null` 또는 공백으로 제출하면 저장된 상세주소를 제거합니다.
- 나머지 수정 필드는 모두 필수입니다. 일부 필드만 보내는 부분 수정은 제공하지 않습니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 병원 관계자가 자기 응급실 위치와 연락처를 저장 | 모든 값을 한 트랜잭션으로 검증·수정하고 자기 병원 프로필 전체를 반환하며 수신 `ON/OFF`는 유지 |
| 2 | 구급대원이 자기 이름과 회신 연락처를 저장 | 이름·연락처를 함께 수정하고 동의 정보를 포함한 자기 프로필 전체를 반환 |
| 3 | 프로필 수정 전에 이송 요청 또는 병원 제안이 이미 생성됨 | 기존 요청의 회신 연락처와 기존 제안의 병원 주소·좌표·연락처는 당시 스냅샷을 유지하고 새 요청·새 제안부터 수정값 사용 |
| 4 | 주소·좌표·이름·연락처 중 하나가 검증에 실패 | HTTP 400을 반환하고 같은 요청의 다른 필드도 저장하지 않음 |
| 5 | 다른 역할·조직이 수정하거나 같은 프로필을 동시에 저장 | 다른 사용자의 정보는 변경하지 않고, 허용된 동시 요청은 순서대로 처리해 완전한 한 요청 단위 상태만 저장 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 자기 병원 프로필 수정 | `PUT /api/v1/hospitals/me`, 성공 `200 OK`, 수정 후 `GET /api/v1/hospitals/me`와 같은 전체 병원 프로필 반환 |
| 자기 구급대원 프로필 수정 | `PUT /api/v1/paramedics/me`, 성공 `200 OK`, 수정 후 `GET /api/v1/paramedics/me`와 같은 전체 구급대원 프로필 반환 |
| 동일 값 재전송 | 같은 프로필 필드 상태를 유지하며 중복 프로필이나 이송 데이터를 만들지 않음 |
| 수정 감사 | 민감한 필드 원문 없이 행위자·조직·대상 공개 ID·서버 시각·추적 ID를 감사 기록으로 보존 |

### 자기 병원 프로필 수정 요청

```json
{
  "address": "서울특별시 성북구 삼선교로 16길",
  "detailAddress": "본관 1층 응급의료센터",
  "latitude": 37.5821000,
  "longitude": 127.0105000,
  "contact": "02-1234-5678"
}
```

| 필드 | 필수 | Nullable | 제약 |
|---|---:|---:|---|
| `address` | O | X | 앞뒤 공백 제거 후 1~255자 |
| `detailAddress` | X | O | 앞뒤 공백 제거 후 최대 200자, `null`·공백은 저장값 제거 |
| `latitude` | O | X | -90 이상 90 이하 |
| `longitude` | O | X | -180 이상 180 이하 |
| `contact` | O | X | 기존 가입 연락처 정책과 동일, 앞뒤 공백 제거 후 최대 30자 |

- 주소와 좌표의 실제 일치 여부는 병원 웹에서 지도 확인 후 제출합니다.
- 서버는 이번 기능에서 외부 Geocoding API를 호출하지 않고 문자열·길이·좌표 범위를 검증합니다.
- 수정 요청은 `receivingStatus`를 받지 않으며 기존 수신 상태를 그대로 유지합니다.

### 자기 구급대원 프로필 수정 요청

```json
{
  "displayName": "김민준",
  "callbackContact": "010-1234-5678"
}
```

| 필드 | 필수 | Nullable | 제약 |
|---|---:|---:|---|
| `displayName` | O | X | 앞뒤 공백 제거 후 2~50자, 제어문자 금지 |
| `callbackContact` | O | X | 기존 가입 연락처 정책과 동일, 앞뒤 공백 제거 후 최대 30자 |

- 기존 연락처 수집·이용 및 병원 제공 동의가 유효한 계정만 수정할 수 있습니다.
- 연락처 값 변경은 기존 동의 목적 안의 정보 최신화이므로 동의를 새로 생성하거나 버전을 변경하지 않습니다.

| 수정 후 새로 생성하는 병원 제안 | 최신 병원 프로필 사용 |
| 구급대원 이름과 기존 감사 행위자 | 계정 식별·기존 감사 기록은 변경하지 않음 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `HOSPITAL_STAFF` | 자기 병원 위치·연락처 수정 | JWT 계정·조직에 연결된 병원 프로필 한 건 |
| `PARAMEDIC` | 자기 이름·회신 연락처 수정 | JWT 계정·조직에 연결된 구급대원 프로필 한 건 |
| `SUPER_ADMIN` | 없음 | 병원·구급대원 프로필 대리 수정 불가 |
| 미인증 사용자 | 없음 | 인증 필요 |

- 경로·Query·요청 본문으로 계정 ID, 조직 ID 또는 프로필 ID를 입력받지 않습니다.
- 서버는 JWT의 계정 ID·조직 ID·역할을 현재 DB의 활성 계정·조직·프로필과 다시 대조합니다.

|---|---|---:|

| 인증정보 없음 | `AUTH_001` | 401 |
