# 구급대원 회원가입·프로필 연동 보완 요구사항

```text
Feature: signup-profile-integration
Owner: backend
Related Issue: NONE
Frontend Impact: FLUTTER_PARAMEDIC
Policy Decision Status: RESOLVED
```

> Flutter 구급대원 앱의 가입 코드 확인, 회원가입, 로그인 후 사용자 정보 복구에
> 필요한 백엔드 계약을 완성하는 기능입니다. 기존 조직 가입·JWT 인증 흐름은
> 유지하고 구급대원 화면에 필요한 이름과 개인정보 동의 정보를 보완합니다.

## 목적

- 회원가입 전에 가입 코드가 유효한지 확인하고 소속 구급대와 역할을 화면에 표시합니다.
- 구급대원 회원가입 시 화면에 표시할 이름과 필수 개인정보 동의 2개를 함께 저장합니다.
- 로그인 또는 앱 재실행 후 인증된 구급대원이 자신의 계정·소속·연락처·동의 정보를 다시 조회합니다.
- 가입 코드 원문, 비밀번호와 토큰을 응답·로그·프로필에 불필요하게 노출하지 않습니다.

## 이번 기능 범위

### 포함

- 구급대원 가입 코드 사전 확인 API
- 구급대원 회원가입의 `displayName` 입력 및 저장
- 연락처 수집·이용 동의와 요청 수신 병원 제공 동의의 분리 기록
- 인증된 구급대원의 내 프로필 조회 API
- 기존 Dev 구급대원 계정의 표시 이름·동의 이력 호환
- Flutter 구급대원 앱 연동 문서

### 제외

- 가입 코드 생성·조회·폐기 정책 변경
- 로그인 ID·비밀번호·JWT 발급 및 갱신 정책 변경
- 프로필 이름·연락처 수정
- 로그아웃 및 Refresh Token 폐기 API
- 최근 이송 목록 조회
- 병원 공용 계정의 회원가입 화면·프로필 계약 변경
- 실제 운영용 개인정보 동의 문구와 보존·삭제 기간 확정

## 정책 기준

### 기존 MVP·구현 기준

- 구급대원은 가입 코드로 확인된 `EMS_UNIT` 조직의 개인 계정을 사용합니다.
- 가입 코드는 조직과 역할에 연결된 일회용 코드이며 서버에는 원문 대신 해시만 저장합니다.
- 가입 코드는 `AVAILABLE`일 때만 사용할 수 있고 사용·만료·폐기 상태를 구분합니다.
- 로그인 ID는 영문 소문자와 숫자 4~30자이며 대문자는 허용하지 않습니다.
- 비밀번호는 8~64자이며 단방향 해시로 저장합니다.
- 구급대원은 가입 시 병원 회신용 연락처를 등록하고, 이송 요청에는 서버가 계정의 연락처를 자동 연결합니다.
- 실제 개인정보, 비밀번호, 토큰과 가입 코드 원문을 로그에 남기지 않습니다.

### 이번 기능에서 확정한 기준

#### 가입 코드 사전 확인

- 미인증 사용자가 `POST /api/v1/auth/invitations/validate`에 가입 코드를 요청 본문으로 제출합니다.
- 성공 시 소속 조직 ID·이름, 대상 역할, 코드 만료 시각과 구급대원 가입에 필요한 현재 동의 유형·문구 버전을 반환합니다.
- Flutter 구급대원 가입 화면은 반환 역할이 `PARAMEDIC`인지 확인하고 소속 구급대를 표시합니다.
- 사용자가 가입 코드를 입력하고 `가입 코드 확인`을 누르는 동작은 1단계에서 한 번만 수행합니다.
- 확인에 성공하면 앱은 처음 입력한 코드 원문을 회원가입 흐름이 끝날 때까지만 메모리에 보관하고 2단계 계정 정보 화면으로 이동합니다.
- 2단계에서는 가입 코드를 다시 입력하거나 별도로 확인하지 않습니다.
- 가입 코드는 앞뒤 공백만 제거하고 대소문자를 바꾸지 않습니다. 대문자 변환이나 소문자 변환을 하면 다른 코드로 취급합니다.
- 사전 확인은 가입 코드를 소비하거나 상태를 바꾸지 않습니다.
- 최종 `회원가입`을 누르면 앱이 보관 중인 코드 원문을 회원가입 요청에 자동으로 포함합니다. 이는 사용자에게 코드를 다시 요구하는 동작이 아닙니다.
- 사전 확인 후 실제 가입 전까지 코드가 사용·만료·폐기될 수 있으므로 서버는 회원가입 트랜잭션 안에서 사용 가능 여부를 다시 검증하고 성공할 때 한 번만 소비합니다.
- 앱은 회원가입 완료, 취소 또는 가입 흐름 이탈 시 보관한 가입 코드 원문을 제거하며 기기 영구 저장소에 저장하지 않습니다.
- 가입 코드 원문은 응답에 되돌려주지 않으며 URL, 오류 메시지와 로그에 포함하지 않습니다.

#### 구급대원 이름

- 구급대원 회원가입 요청에 `displayName`을 필수로 추가합니다.
- 앞뒤 공백을 제거한 값이 2~50자여야 하고 공백만으로 구성할 수 없습니다. 이름의 문자 종류를 영문으로 제한하지 않습니다.
- 표시 이름은 로그인 ID나 인증 권한을 대신하지 않으며 화면 표시 용도로만 사용합니다.
- 표시 이름은 병원 요청과 환자정보에 자동 공개하지 않습니다.
- 이 기능 적용 전에 생성된 Dev 구급대원 계정은 로그인 ID를 표시 이름으로 보완해 프로필 조회가 실패하지 않게 합니다.

#### 개인정보 동의 2개

- 구급대원 가입 화면은 다음 두 항목을 각각 필수로 받습니다.
  - 연락처 수집·이용 동의
  - 이송 요청을 받은 병원에 연락처를 제공하는 동의
- 각 항목은 동의 여부, 서버가 관리하는 문구 버전과 서버 동의 시각을 구분해 기록합니다.
- 둘 중 하나라도 동의하지 않았거나 제출한 버전이 현재 서버 버전과 다르면 가입하지 않습니다.
- 신규 구급대원 가입 API는 두 동의 정보를 모두 요구합니다.
- 기존 단일 `연락처 수집·제공 동의`로 생성된 Dev 계정은 기존 기능 사용을 막지 않으며, 프로필 조회에서는 레거시 동의 이력임을 구분할 수 있게 반환합니다.
- 병원 회원가입의 기존 연락처 동의 요청 형식은 이번 기능에서 변경하지 않습니다.

#### 내 프로필 조회

- 인증된 구급대원은 `GET /api/v1/paramedics/me`로 자신의 프로필만 조회합니다.
- 응답에는 계정 ID, 로그인 ID, 표시 이름, 소속 조직 ID·이름, 역할, 회신 연락처와 동의 이력을 포함합니다.
- 동의 이력은 동의 유형, 문구 버전과 서버 동의 시각으로 구분합니다.
- 비밀번호 해시, 가입 코드, Access Token과 Refresh Token은 반환하지 않습니다.
- 계정 ID를 요청값으로 받지 않고 검증된 Access Token의 계정을 사용합니다.

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 가입 코드 사전 확인 | 1단계에서 사용자가 입력한 코드를 `POST /api/v1/auth/invitations/validate`에 제출하고 조직·역할·만료 시각·필수 동의 유형과 현재 문구 버전을 받으며 코드는 소비되지 않음 |
| 구급대원 회원가입 | 2단계에서 앱이 보관한 코드와 사용자가 입력한 이름·로그인 정보·연락처·필수 동의 2개를 `POST /api/v1/auth/signups/paramedic`에 자동 제출하고 성공 시 코드를 소비함 |
| 로그인 | 기존 `POST /api/v1/auth/login` 계약으로 Access·Refresh Token을 발급받음 |
| 내 프로필 조회 | `GET /api/v1/paramedics/me`에 Access Token을 보내 현재 구급대원의 화면 표시 정보를 받음 |
| 토큰 갱신 후 복구 | 기존 토큰 갱신 API로 인증을 복구한 뒤 내 프로필을 다시 조회함 |

## 기존 API 호환성

- 가입 코드 발급·관리, 로그인과 토큰 갱신 API는 변경하지 않습니다.
- 구급대원 회원가입에는 `displayName`과 분리된 동의 2개가 필수로 추가되므로 기존 구급대원 가입 요청 본문은 검증 오류가 발생합니다.
- Flutter는 새 핸드오프의 실제 필드명과 동의 버전을 기준으로 회원가입 요청을 전환해야 합니다.
- 병원 회원가입 API와 React 병원·관리자 웹 계약은 이번 기능에서 변경하지 않습니다.
- 기존 Dev 구급대원 계정과 진행 중인 이송 데이터는 삭제하지 않고 마이그레이션으로 보완합니다.

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| 미인증 사용자 | 가입 코드 사전 확인, 구급대원 회원가입, 로그인 | 제출한 가입 코드와 가입 정보의 검증 결과만 확인 |
| `PARAMEDIC` | 내 프로필 조회 | 인증된 자신의 계정·소속·연락처·동의 이력만 조회 |
| `HOSPITAL_STAFF` | 가입 코드 사전 확인 가능, 구급대원 프로필 조회 불가 | 구급대원 개인정보에 접근 불가 |
| `SUPER_ADMIN` | 기존 조직·가입 코드 관리만 가능 | 구급대원 회신 연락처와 프로필 조회 불가 |

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
