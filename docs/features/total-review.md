## 1. 차단 문제

### P1. 거절 병원의 환자정보 조회 범위 충돌

현재 정책 문서와 구현이 다릅니다.

```text
병원이 요청 거절
→ 병원 카드가 HISTORY로 이동
→ 현재 구현에서는 거절 시점 환자정보 상세 조회 가능
```

- 기능 12는 종료 이력에서 임상정보를 제거하고 상세 조회를 `404`로 차단합니다.
- 기능 17과 현재 구현은 거절 병원이 거절 시점의 환자정보를 계속 조회할 수 있게 합니다.
- 현재 테스트도 상세 조회 `200`과 거절 시점 활력징후 반환을 기대합니다.

다음 중 하나를 정책으로 확정해야 합니다.

| 선택 | 동작 |
|---|---|
| 권장 | 거절 즉시 환자정보 상세 조회 차단, HISTORY에는 거절 사유·처리 시각만 표시 |
| 대안 | 거절 시점의 고정된 환자정보는 계속 제공하고 이후 갱신만 차단 |

정책 확정 후 `REJECTED`와 레거시 종료 상태의 목록 DTO, 상세 API와 비노출 테스트를
같이 정렬해야 합니다. 해결 전에는 다음 기능 개발보다 이 항목을 먼저 처리합니다.

## 2. 후속 리스크

| 심각도 | 문제 | 필요한 조치 |
|---|---|---|
| P2 | 공개 가입 코드 확인 API에 요청 제한과 실패 감시가 없음 | IP·코드 기준 제한과 감시 정책 추가 |
| P2 | 롤백 시 이전 이미지도 새 Secret을 사용해 설정 오류는 복구하지 못할 수 있음 | 이미지 실패와 설정 실패의 복구 정책 분리 |
| P2 | 기능 05 핸드오프에서 최신 15~17 계약으로 바로 이동할 수 없음 | 후속 핸드오프 링크 추가 |
| P2 | HTTP Dev 서버의 가짜 데이터 전용 제한이 최신 핸드오프에 없음 | 실제 환자·계정·GPS 사용 금지 명시 |
