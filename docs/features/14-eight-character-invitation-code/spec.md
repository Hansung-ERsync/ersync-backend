# 8자리 가입 코드 발급 요구사항

```text
Feature: eight-character-invitation-code
Owner: backend
Related Issue: 리뷰 항목 3 - 가입 코드 입력 길이 단축
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

> 새로 발급하는 가입 코드를 기존 Base64 URL 문자 체계는 유지하면서 정확히
> 8자리로 줄여, 슈퍼 관리자가 전달하고 병원·구급대원이 입력할 때 발생하는
> 실수를 줄이는 기능입니다. 기존에 발급된 긴 코드는 유효기간과 상태가 허용하는
> 동안 계속 사용할 수 있습니다.

## 목적

- 현재 약 43자인 가입 코드를 사람이 전달·입력하기 쉬운 8자리로 줄입니다.
- 가입 코드 전용 난수 생성만 변경하고 Refresh Token의 보안 강도는 그대로 유지합니다.
- 코드 원문 1회 표시, SHA-256 다이제스트 저장, 만료·폐기·1회 사용 정책을 유지합니다.
- 배포 전에 발급된 기존 긴 코드가 갑자기 무효화되는 호환성 문제를 방지합니다.

## 현재 문제

- 현재 `SecretDigester.generate()`는 32바이트 난수를 Base64 URL 문자열로 바꿔
  약 43자인 가입 코드를 만듭니다.
- 같은 생성기는 Refresh Token에도 사용되므로 공통 길이를 줄이면 인증 토큰의
  보안 강도까지 함께 낮아집니다.
- 긴 가입 코드는 복사·붙여넣기는 가능하지만 구두·메신저 전달 또는 모바일 직접
  입력 과정에서 누락과 오타 가능성이 큽니다.
- 가입 코드 원문은 발급 응답에서 한 번만 확인할 수 있으므로 최초 전달 오류가
  발생하면 새 코드를 다시 발급해야 합니다.

## 이번 기능 범위

### 포함

- 새로 발급하는 가입 코드 길이를 정확히 8자로 변경
- 기존 Base64 URL 문자 집합 유지
  - 영문 대문자 `A-Z`
  - 영문 소문자 `a-z`
  - 숫자 `0-9`
  - 기호 `-`, `_`
- `SecureRandom` 기반 6바이트 난수를 패딩 없는 Base64 URL로 변환해 균등한
  8자리 코드 생성
- 가입 코드의 대소문자 구분 유지
- 코드 앞뒤 공백 제거 후 검증하는 기존 입력 처리 유지
- 새 코드 원문은 발급 성공 응답에서 한 번만 반환
- DB에는 기존과 같이 SHA-256 다이제스트만 저장
- 기존에 발급된 긴 코드의 사전 확인·회원가입 호환 유지
- 중복 다이제스트 방지와 생성 충돌 검증
- 관리자 웹, Flutter 구급대원 앱과 React 병원 웹 핸드오프

### 제외

- Refresh Token과 다른 보안 Secret 길이 변경
- 기존 가입 코드 원문을 DB에서 조회하거나 복구하는 기능
- 이미 발급된 코드의 원문·다이제스트·만료일 일괄 변경
- 가입 코드를 대소문자 구분 없이 처리하는 정규화
- 숫자 전용 코드, 구분자 자동 삽입, 체크섬 또는 사람이 정한 코드
- 가입 코드 유효기간, 조직·역할 연결, 상태와 1회 사용 정책 변경
- 관리자 목록에 코드 원문 재노출
- Flutter·React 코드 직접 수정

## 정책 기준

- 적용할 MVP 요구사항:
  - 슈퍼 관리자가 조직과 역할에 묶인 가입 코드를 발급합니다.
  - 코드 원문은 한 번만 표시하고 DB에는 해시만 저장합니다.
  - 코드는 유효기간 안에 한 번만 사용할 수 있습니다.
  - 사용·만료·폐기 상태와 감사기록을 유지합니다.
- 기존 정책과 충돌: 없음
- 보안 기준:
  - 64개 문자 중 8자를 균등하게 생성하므로 가능한 조합은 `64^8`, 즉
    `281,474,976,710,656`개이며 48비트 난수 공간을 가집니다.
  - 코드가 짧아져도 원문을 저장·로그에 남기지 않는 기존 규칙을 유지합니다.
  - Refresh Token은 기존 32바이트 난수 생성을 그대로 사용합니다.

## 확정 외부 계약

### 신규 코드 발급

기존 관리자 API를 그대로 사용합니다.

```text
POST /api/v1/admin/invitation-codes
```

- 성공 상태: `201 Created`
- 응답 `code`: 정확히 8자
- 신규 코드 정규식: `[A-Za-z0-9_-]{8}`
- 응답 `invitation`의 조직·역할·상태·만료 시각 계약은 변경하지 않습니다.
- 코드 원문은 이 응답에서만 한 번 제공하며 이후 목록·조회 응답에는 없습니다.

### 코드 사전 확인과 회원가입

기존 API를 그대로 사용합니다.

```text
POST /api/v1/auth/invitations/validate
POST /api/v1/auth/signups/paramedic
POST /api/v1/auth/signups/hospital
```

- 새 8자리 코드와 배포 전에 발급된 기존 긴 코드를 모두 허용합니다.
- 입력 앞뒤 공백은 제거하지만 내부 문자는 바꾸지 않습니다.
- 대문자와 소문자는 서로 다른 코드로 취급합니다.
- 사전 확인은 코드를 소비하지 않고, 회원가입 성공만 코드를 `USED`로 전환합니다.
- 사용·만료·폐기 코드는 기존 오류 계약을 유지합니다.

### 코드 목록과 폐기

```text
GET /api/v1/admin/invitation-codes
POST /api/v1/admin/invitation-codes/{invitationCodeId}/revoke
```

- 목록은 코드 길이 변경과 관계없이 원문과 다이제스트를 반환하지 않습니다.
- `invitationCodeId`는 관리용 공개 ID이며 8자리 가입 코드와 다른 값입니다.
- 폐기는 기존처럼 `AVAILABLE` 상태의 코드에만 허용합니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 슈퍼 관리자가 병원 또는 구급대 조직의 가입 코드를 발급 | Base64 URL 문자로 된 정확히 8자리 원문을 한 번 반환하고 DB에는 SHA-256 다이제스트만 저장 |
| 2 | 앱·웹이 새 8자리 코드를 사전 확인한 뒤 회원가입 | 조직과 역할을 확인하고 가입 성공 시 코드가 한 번만 `USED`로 전환됨 |
| 3 | 배포 전에 발급된 아직 유효한 긴 코드를 입력 | 기존 코드도 사전 확인과 회원가입이 정상 동작함 |
| 4 | 새 코드의 알파벳 대소문자를 바꾸거나 한 글자를 잘못 입력 | 다른 다이제스트가 조회되어 `INVITATION_001`로 거절됨 |
| 5 | 생성된 후보 코드가 저장된 코드와 중복 | 중복 원문을 반환하지 않고 새 난수를 다시 생성하며 DB 유니크 제약도 최종 방어선으로 유지됨 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 가입 코드 발급 | 기존 발급 API 응답의 `code`가 새 발급분부터 정확히 8자리 |
| 코드 전달 | 한 번 반환된 원문을 복사하거나 직접 입력해 전달 |
| 코드 사전 확인 | 새 8자리와 기존 긴 코드를 모두 검증하며 상태는 소비하지 않음 |
| 회원가입 | 기존 조직·역할 검증 뒤 성공한 한 계정만 코드를 소비 |
| 목록·폐기 | 원문 비공개와 기존 상태 전이 계약 유지 |

## 기존 API 호환성

- API 경로, 요청 필드명과 응답 구조는 변경하지 않습니다.
- 발급 응답 `code`의 실제 길이만 신규 발급분부터 짧아집니다.
- 기존 긴 코드 입력을 서버에서 계속 허용하므로 배포 시점의 `AVAILABLE` 코드는
  만료·사용·폐기 전까지 유효합니다.
- 프론트는 전환 기간에 가입 코드 입력을 정확히 8자로만 제한하지 않고 기존 긴
  코드도 전송할 수 있어야 합니다.
- 새 코드를 화면에 표시할 때 대문자 변환, 소문자 변환 또는 내부 공백 삽입을
  하지 않습니다.

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 신규 코드 길이 | 정확히 8자리 | 사람이 전달·입력할 때 발생하는 오류를 줄임 |

| DB 변경 | 없음 | 기존 SHA-256 `BINARY(32)` 다이제스트와 유니크 제약을 그대로 사용 |
