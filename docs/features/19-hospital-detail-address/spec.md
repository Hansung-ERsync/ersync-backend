# 병원 상세주소 및 목적지 정보 요구사항

```text
Feature: 19-hospital-detail-address
Owner: Backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

## 목적

- 병원 가입 시 응급실의 선택 상세주소를 보존하고 자기 프로필에서 복구합니다.
- 구급대원이 수락 병원의 실제 응급실 위치를 확인하고 목적지를 선택할 수 있게 합니다.

## 정책 기준

- 적용할 MVP 요구사항: 병원은 응급실 주소·좌표를 등록하고 구급대원은 수락 병원의 위치를 확인합니다.
- 기존 정책과 충돌: 없음

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 병원이 도로명 주소와 상세주소로 가입 | 상세주소를 trim해 저장하고 자기 프로필에 반환 |
| 2 | 병원이 상세주소를 생략하거나 공백만 입력 | 가입은 성공하고 상세주소는 `null`로 저장 |
| 3 | 병원이 이송 요청을 수락 | 구급대원 병원 카드에 제안 당시 주소·상세주소·좌표 제공 |
| 4 | 병원이 응답 대기·거절·철회 상태 | 구급대원 응답에서 주소·좌표를 제공하지 않음 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 병원 가입 | `detailAddress` 선택 입력 추가, 최대 200자 |
| 병원 자기 프로필 조회 | 저장된 `detailAddress`를 nullable 필드로 반환 |
| 구급대원 병원 검색 조회 | `ACCEPTED` 제안에만 병원 주소·상세주소·좌표 반환 |
| 병원 제안 생성 | 병원 주소·상세주소를 제안 시점 값으로 고정 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| 공개 가입 사용자 | 가입 코드로 병원 주소 제출 | 해당 코드의 병원 조직 |
| `HOSPITAL_STAFF` | 자기 병원 프로필 조회 | 자기 병원 저장 정보 |
| `PARAMEDIC` | 자기 이송 요청의 수락 병원 위치 조회 | 자신이 생성한 요청의 `ACCEPTED` 제안 |
| `SUPER_ADMIN` | 변경 없음 | 병원 프로필·이송 위치 조회 불가 |

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 상세주소 200자 초과 | `COMMON_001` | 400 |
| 주소·좌표 기존 검증 실패 | `COMMON_001` | 400 |
| 다른 구급대원의 요청 조회 | 기존 요청 소유권 오류 | 404 |
| 병원 자기 프로필 역할·조직 불일치 | 기존 인증·권한 오류 | 401 또는 403 |

## 완료 조건

- [ ] 병원 상세주소가 가입 요청에서 DB와 자기 프로필까지 보존됨
- [ ] 병원 제안에 주소·상세주소가 스냅샷됨
- [ ] `ACCEPTED` 병원만 구급대원에게 주소·상세주소·좌표가 공개됨
- [ ] 기존 데이터·활성 API·거리·ETA 계산이 회귀하지 않음
- [ ] React·Flutter 핸드오프가 실제 응답 계약과 일치함

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 상세주소 필수 여부 | 선택, 최대 200자 | 주소만으로 식별 가능한 병원 허용 |
| 기존 병원 수정 | 수정 API를 추가하지 않음 | 이번 기능은 신규 가입 계약만 확장 |

| 이송 중 주소 일관성 | 제안 생성 시 스냅샷 | 진행 중 제안이 프로필 변경 영향을 받지 않음 |
