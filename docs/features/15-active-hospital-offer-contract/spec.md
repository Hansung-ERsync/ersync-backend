# 비목적지 병원 제안 활성 상태 요구사항

```text
Feature: active-hospital-offer-contract
Owner: backend
Related Issue: NONE
Frontend Impact: REACT_HOSPITAL_ADMIN
Policy Decision Status: RESOLVED
```

> 2026-08-13 확정된 목적지 이후 병원 상태·정보 노출 정책을 현재 구현에
> 반영하는 기능입니다. 새로운 제품 정책을 추가하지 않습니다.

## 목적

- 목적지를 선택한 뒤에도 비목적지 `PENDING`·`ACCEPTED` 제안을 활성 상태로 유지합니다.
- 병원은 허용된 수락·거절·철회 동작을 계속할 수 있습니다.
- 비목적지 병원에는 목적지 선택 이후의 임상 갱신과 정확한 위치를 노출하지 않습니다.
- 전체 이송 상태, 병원의 실제 응답과 현재 목적지 여부를 서로 구분합니다.

## 정책 기준

- 적용 기준은 MVP 요구사항 13장과 14장, 기능 05·12의 확정 정책입니다.
- 현재 목적지는 최대 한 곳이며 수락만으로 목적지가 되지 않습니다.
- 목적지 선택은 다른 병원의 제안을 종료하거나 이력으로 이동시키지 않습니다.
- 비목적지 `PENDING`은 `AWAITING_RESPONSE`이며 `HANDOFF_REQUESTED` 전까지 계속 수락·거절할 수 있습니다.
- 비목적지 `ACCEPTED`는 `ACCEPTED`이며 `HANDOFF_REQUESTED` 전까지 철회하거나 목적지로 선택될 수 있습니다.
- 목적지가 있으면 비목적지 `PENDING`에는 `다른 병원으로 이동 중 · 응답 가능`,
  비목적지 `ACCEPTED`에는 `수락 완료 · 다른 병원으로 이동 중`을 표시합니다.
- 진행 중 요청에서는 다른 목적지가 있다는 이유로 `NOT_SELECTED`를 만들지 않습니다.
- 목적지 선택 전에는 `PENDING`·`ACCEPTED` 병원이 최신 최소 임상정보를 볼 수 있습니다.
- 목적지 선택 후에는 현재 목적지만 새로 추가되는 임상정보·임상 이력과 정확한 위치를 볼 수 있습니다.
- 최초 목적지를 선택하면 모든 비목적지 병원의 환자정보와 `lastClinicalUpdateAt`은 그 선택 시점에 보이던 값으로 고정합니다.
- 목적지를 변경하면 이전 목적지는 변경 시점에 보이던 값으로 고정하고, 새 목적지는 최신 정보와 이후 갱신을 받습니다.
- 목적지로 다시 선택되지 않은 병원의 기존 정보 고정 시점은 목적지 변경으로 갱신하지 않습니다.
- 목적지가 있는 동안 늦게 수락한 병원도 기존 정보 고정 시점을 유지합니다.
- 비목적지 병원에는 이송 중 갱신되는 경로 거리·ETA와 최근 성공 ETA를 제공하지 않습니다.
- 비목적지 병원에 실제 목적지 병원의 식별정보를 노출하지 않습니다.

이번 기능에서는 목적지 병원의 긴급 철회 재검색과 `NO_RESPONSE`, 후보 소진,
전체 재전송 계약을 변경하지 않습니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | A·B 수락, C 응답 대기 후 구급대원이 A 선택 | A는 현재 목적지, B는 활성 `ACCEPTED`, C는 활성 `AWAITING_RESPONSE` |
| 2 | A 선택 뒤 새로운 임상정보가 추가됨 | A만 새 정보를 보고 B·C는 마지막 허용 정보만 조회 |
| 3 | A가 목적지인 동안 C가 늦게 수락함 | C는 활성 `ACCEPTED`가 되지만 목적지는 A로 유지 |
| 4 | 구급대원이 목적지를 A에서 B로 변경함 | B가 유일한 목적지, A는 활성 `ACCEPTED`를 유지하고 이후 갱신은 받지 않음 |
| 5 | 요청이 완료되거나 취소됨 | 모든 활성 카드가 이력으로 이동하고 기존 병원 응답 결과는 보존 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 병원 활성 목록 조회 | `GET /api/v1/hospitals/me/offers?view=ACTIVE`; 비목적지 `PENDING`·`ACCEPTED` 포함 |
| 병원 이력 목록 조회 | `GET /api/v1/hospitals/me/offers?view=HISTORY`; 진행 중 비목적지 제안 제외 |
| 병원 제안 상세 조회 | `GET /api/v1/hospitals/me/offers/{offerId}`; 병원별 허용 시점까지의 정보 반환 |
| 임상 이력 조회 | `GET /api/v1/hospitals/me/offers/{offerId}/clinical-timeline`; 현재 목적지가 아니면 허용 시점 이후 기록 제외 |
| 위치·ETA 조회 | `GET /api/v1/hospitals/me/offers/{offerId}/location`; 현재 목적지 병원만 허용 |
| 병원 응답 | 기존 수락·거절·철회 API 유지; 비목적지 상태에서도 정책상 허용된 명령 처리 |
| 상태 표시 | `hospitalOutcome`, `offerStatus`, `currentDestination` 조합으로 현재 상태 확정 |
| 실시간 갱신 | 최소 SSE 신호 수신 후 목록·상세를 다시 조회하며 이벤트에 임상정보·좌표를 포함하지 않음 |

진행 중 비목적지 병원의 응답 계약은 다음과 같습니다.

| 요청 상태 | `offerStatus` | `hospitalOutcome` | `currentDestination` | 허용 동작 |
|---|---|---|---:|---|
| `EN_ROUTE` 이전·이송 중 | `PENDING` | `AWAITING_RESPONSE` | `false` | 수락·거절 |
| `EN_ROUTE` 이전·이송 중 | `ACCEPTED` | `ACCEPTED` | `false` | 수락 철회, 구급대원의 목적지 선택 |
| `EN_ROUTE` | `ACCEPTED` | `ACCEPTED` | `true` | 수락 철회, 인계 완료 요청 |
| `HANDOFF_REQUESTED` | `PENDING`·`ACCEPTED` | 기존 결과 유지 | 목적지 병원만 `true` | 현재 목적지 병원의 인계 확인만 허용 |
