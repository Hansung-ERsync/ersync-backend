# 역할별 로그인 아이디 및 로그인 역할 지정 요구사항

```text
Feature: role-scoped-login-id
Owner: backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

> 구급대원 앱과 병원·관리자 웹이 로그인할 계정 역할을 명시하고, 같은 로그인
> 아이디를 서로 다른 역할에서 사용할 수 있게 하는 기능입니다. 계정 DB는
> 분리하지 않으며 서버가 아이디와 역할을 함께 검증해 실제 계정을 식별합니다.

## 목적

- `PARAMEDIC`, `HOSPITAL_STAFF`, `SUPER_ADMIN`이 같은 문자열의 로그인 아이디를 각각 사용할 수 있게 합니다.
- 같은 역할 안에서는 로그인 아이디 중복을 계속 금지합니다.
- 로그인할 때 클라이언트가 사용하는 서비스의 역할을 고정해 전송하고, 서버는 `loginId + role + password`를 함께 검증합니다.
- 역할값을 클라이언트 권한으로 신뢰하지 않고 DB에서 조회한 실제 계정의 역할·조직으로 JWT와 접근 권한을 결정합니다.
- 기존 계정, Refresh Token과 발급된 Access Token을 삭제하지 않고 새 계약으로 전환합니다.

## 이번 기능 범위

### 포함

- 계정 로그인 아이디 고유성 범위를 전체 시스템에서 `loginId + role` 조합으로 변경
- 병원·구급대원 회원가입의 역할별 로그인 아이디 중복 검증
- 로그인 요청에 필수 `role` 추가
- 역할과 아이디를 함께 사용하는 계정 조회 및 로그인 실패 처리
- 슈퍼 관리자 bootstrap의 역할별 아이디 중복 처리
- 기존 계정과 인증 토큰을 유지하는 Flyway migration
- Flutter 구급대원 앱과 React 병원·관리자 웹 로그인 전환 핸드오프
- 역할 오선택, 같은 아이디의 두 역할 로그인과 동시 가입 테스트

### 제외

- 계정 테이블 또는 DB를 역할별로 분리
- 같은 역할 안에서 동일 로그인 아이디 허용
- 한 계정에 여러 역할 부여
- 기존 계정의 역할 변경·병합·이동
- 로그인 화면에서 사용자가 임의 역할을 선택하는 UI
- 회원가입 요청 필드, 가입 코드 역할과 조직 정책 변경
- Refresh Token 요청·응답, JWT claim과 토큰 수명 변경
- 로그아웃, 비밀번호 변경·재설정, 로그인 시도 제한 기능
- Flutter·React 저장소의 실제 코드 수정

## 정책 기준

### 기존 MVP·보안 기준

- 구급대원은 `PARAMEDIC` 개인 계정, 병원은 `HOSPITAL_STAFF` 공용 계정, 운영자는 `SUPER_ADMIN` 계정을 사용합니다.
- 병원과 구급대원 계정은 가입 코드에 저장된 조직과 역할로 생성됩니다.
- 병원 조직에는 공용 병원 계정과 병원 프로필을 하나만 생성할 수 있습니다.
- 로그인 아이디는 앞뒤 공백을 제거한 영문 소문자·숫자 4~30자이고 대문자를 허용하지 않습니다.
- 비밀번호는 8~64자이며 단방향 해시로 저장합니다.
- JWT는 서버가 조회한 계정 UUID·조직·역할을 기준으로 발급하고, 보호 API에서 현재 DB 계정과 다시 대조합니다.
- 아이디 또는 비밀번호 중 무엇이 틀렸는지 로그인 오류로 구분해 노출하지 않습니다.

### 이번 기능에서 확정한 기준

#### 로그인 아이디 고유성

- 계정 테이블은 계속 하나만 사용합니다.
- 로그인 아이디의 DB 고유성은 `login_id + role` 조합으로 적용합니다.
- 같은 `loginId`로 `PARAMEDIC`, `HOSPITAL_STAFF`, `SUPER_ADMIN` 계정을 각각 하나씩 만들 수 있습니다.
- 같은 역할 안에서는 조직이 달라도 같은 `loginId`를 다시 사용할 수 없습니다.
- 병원 공용 계정 하나라는 기존 조직 정책은 역할별 아이디 고유성과 별도로 계속 적용합니다.
- 기존 계정은 이미 전체 로그인 아이디가 고유하므로 데이터 수정이나 삭제 없이 새 복합 고유 제약으로 이전합니다.

#### 로그인 요청

- `POST /api/v1/auth/login` 요청에 `role`을 필수로 추가합니다.
- 허용값은 `PARAMEDIC`, `HOSPITAL_STAFF`, `SUPER_ADMIN`입니다.
- 서버는 정규화·검증된 `loginId`와 요청 `role`이 모두 일치하는 계정 한 건을 조회한 뒤 비밀번호와 활성 상태를 검증합니다.
- 요청의 `role`은 계정을 찾기 위한 식별 조건일 뿐 권한 부여 근거가 아닙니다. JWT와 응답 역할은 DB에서 조회한 실제 계정으로 생성합니다.
- 같은 아이디의 다른 역할 계정에 맞는 비밀번호를 입력해도 요청 역할이 다르면 로그인할 수 없습니다.
- 아이디·역할 조합이 없거나 비밀번호가 틀린 경우 모두 기존 `AUTH_004`를 반환해 어떤 계정이 존재하는지 노출하지 않습니다.
- 로그인 성공 응답은 기존과 같으며 `role`에는 실제 로그인된 계정 역할이 반환됩니다.

로그인 요청 예시:

```json
{
  "loginId": "shared01",
  "password": "safe-password",
  "role": "PARAMEDIC"
}
```

#### 클라이언트 역할 고정

- Flutter 구급대원 앱은 로그인 요청마다 `role: PARAMEDIC`을 고정해 전송합니다.
- React 병원 로그인 화면은 `role: HOSPITAL_STAFF`를 고정해 전송합니다.
- React 슈퍼 관리자 로그인 화면 또는 관리자 진입 경로는 `role: SUPER_ADMIN`을 고정해 전송합니다.
- 일반 사용자가 역할을 임의로 선택하는 UI는 만들지 않습니다.
- 로그인 성공 후 응답 `role`이 클라이언트가 요청한 역할과 다르면 토큰을 저장하지 않습니다. 서버도 실제로는 같은 역할 계정만 조회하므로 이는 추가 방어 검증입니다.

#### 회원가입과 동시성

- 병원 회원가입은 가입 코드에 고정된 `HOSPITAL_STAFF` 역할과 로그인 아이디 조합의 중복만 검사합니다.
- 구급대원 회원가입은 가입 코드에 고정된 `PARAMEDIC` 역할과 로그인 아이디 조합의 중복만 검사합니다.
- 다른 역할에 같은 아이디가 있어도 회원가입할 수 있습니다.
- 같은 역할·같은 아이디 가입이 동시에 실행되면 DB 복합 고유 제약으로 한 계정만 생성하고 다른 요청은 `USER_003`으로 실패합니다.
- 역할이 다른 두 가입이 같은 아이디로 동시에 실행되면 각 가입 코드와 조직 조건이 유효한 경우 두 계정 모두 생성될 수 있습니다.

#### 기존 인증정보와 전환

- 기존 계정의 UUID, 비밀번호 해시, 조직, 역할과 상태는 변경하지 않습니다.
- 배포 전에 발급된 Access Token은 기존 검증 규칙과 만료 시각까지 사용할 수 있습니다.
- Refresh Token은 이미 특정 계정 UUID에 연결돼 있으므로 갱신 요청에 역할을 추가하지 않으며 기존 회전 계약을 유지합니다.
- 로그인 요청의 `role`은 필수이므로 이전 요청 형식인 `loginId + password`만 보내면 `COMMON_001` 400을 반환합니다.
- 이번 기능 핸드오프를 로그인 계약의 최신 기준으로 사용합니다.
- 회원가입·가입 코드·토큰 갱신·프로필 등 변경되지 않은 계약은 기존 02·07·09 핸드오프를 계속 참고합니다.
- 현재 Dev 단계의 호환되지 않는 변경이며 백엔드 배포 후 Flutter와 React가 새 로그인 요청으로 전환해야 합니다.

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 병원 회원가입 | 기존 요청 형식 유지, `loginId + HOSPITAL_STAFF` 조합이 없을 때 계정 생성 |
| 구급대원 회원가입 | 기존 요청 형식 유지, `loginId + PARAMEDIC` 조합이 없을 때 계정 생성 |
| 역할 지정 로그인 | `POST /api/v1/auth/login`에 `loginId`, `password`, `role`을 보내 일치하는 활성 계정의 기존 토큰 응답을 받음 |
| 토큰 갱신 | 기존 `POST /api/v1/auth/tokens/refresh` 요청을 그대로 사용하며 역할을 다시 보내지 않음 |

| 슈퍼 관리자 초기 생성 | `SUPER_ADMIN` 계정이 없으면 설정 아이디가 다른 역할에 존재해도 관리자 계정을 생성할 수 있음 |

## 기존 API 호환성

- `POST /api/v1/auth/login`은 필수 `role`이 추가되는 호환되지 않는 변경입니다.
- 로그인 성공 응답, 로그인 오류 형식과 HTTP 상태는 유지합니다.
- 병원·구급대원 회원가입 요청·응답 형식은 유지하고 로그인 아이디 중복 범위만 역할 단위로 변경합니다.
- 토큰 갱신 API와 보호 API의 요청·응답은 변경하지 않습니다.
- 기존 02 로그인 예시는 이번 기능 핸드오프의 로그인 예시로 대체합니다.
- 기존 02·07·09 문서의 회원가입, 가입 코드, 프로필과 토큰 갱신 내용은 계속 유효합니다.
