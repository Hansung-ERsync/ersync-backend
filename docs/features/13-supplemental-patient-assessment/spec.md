# 조건부 추가 환자 평가 저장·조회 요구사항

```text
Feature: supplemental-patient-assessment
Owner: backend
Related Issue: 리뷰 항목 2 - 환자 입력 마지막 단계의 추가정보 API 반영
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

> Flutter 환자 입력 화면에 이미 존재하지만 현재 백엔드로 전송·저장되지 않는
> 개발용 추가 평가 여섯 항목을 최초 이송 요청에 포함하고, 권한이 있는
> 구급대원과 병원이 다시 조회할 수 있게 하는 기능입니다. 의료 검토가 끝나지
> 않은 자동 발동·필수 규칙은 이번 기능에서 만들지 않습니다.

## 목적

- Flutter 앱에서 입력한 혈당·동공·과거력·알레르기·복용약·감염·격리 우려가 실제 API 연동 과정에서 사라지지 않게 합니다.
- 추가 평가를 자유 메모나 기존 환자 snapshot의 임의 문자열로 합치지 않고 구조화된 임상 기록으로 저장합니다.
- 앱 재실행 시 구급대원이 자기 요청의 추가 평가를 복구하고, 병원은 수용 판단 권한이 유지되는 동안 상세 화면에서 확인합니다.
- 슈퍼 관리자와 관계없는 병원에는 추가 임상정보를 제공하지 않습니다.

## 현재 문제

- Flutter `PatientAssessmentDraft`에는 다음 필드가 존재합니다.
  - `glucoseMgDl`
  - `leftPupil`, `rightPupil`
  - `medicalHistory`
  - `allergies`
  - `medications`
  - `isolationConcern`
- 화면에는 `발동 규칙 확정 전 개발용 선택 입력`으로 표시되어 있습니다.
- 현재 Flutter는 이 흐름을 mock data source로만 제출하며, 백엔드의
  `POST /api/v1/transport-requests`에는 해당 입력 필드가 없습니다.
- 따라서 실제 API 연동을 시작하면 사용자가 입력한 추가 평가를 서버에 보낼 수 없고, 앱 재실행이나 병원 상세 조회에서도 복구할 수 없습니다.
- 2026-08-07 Flutter `main`의 `463c86b`까지 다시 확인한 결과 실제 API
  Repository가 추가되었지만 생성 요청 본문에는 위 여섯 항목이 여전히 포함되지
  않으며, 서버 상세 응답에서도 복구하지 않습니다.

  - 주요 과거력

- 심정지 상세
- 중증 외상 상세
- 흉통·심혈관 의심 상세

migration으로 추가합니다. 이번 기능의 공통 append-only 기반은 이 확장이 기존
여섯 항목과 공개 API를 깨지 않도록 설계합니다.

## 정책 기준

- 적용할 MVP 요구사항:
  - 상황별 추가 평가는 모든 환자에게 일괄 요구하지 않고 프로토콜 조건에 맞을 때 사용합니다.
  - 임상정보는 자유 메모 하나가 아니라 구조화된 기록으로 보존합니다.
  - 임상 발생·측정 시각, 앱 입력 시각과 서버 수신 시각을 구분합니다.
  - 최초 병원 요청에는 수용 판단에 필요한 임상정보만 제공하고 환자 직접 식별정보는 제공하지 않습니다.
  - 목적지 선택 뒤에는 현재 목적지 병원에만 이후 임상정보를 제공합니다.
  - 슈퍼 관리자는 환자 임상정보를 조회할 수 없습니다.
- 기존 정책과 충돌: 없음
- 의료 검토 상태:
  - 현재 `ERSYNC_MVP_1.0`은 개발용 프로토콜이며 추가 평가 발동·필수 규칙은 확정되지 않았습니다.
  - 이번 기능은 저장·복구 계약만 제공하며 입력 누락을 정상·음성·확인 불가로 해석하지 않습니다.

## 확정 외부 계약

### 최초 이송 요청

기존 `POST /api/v1/transport-requests` 본문에 다음 객체를 선택적으로 추가합니다.

```json
{
  "supplementalAssessment": {
    "assessedAt": "2026-08-07T10:00:00Z",
    "enteredAt": "2026-08-07T10:01:00Z",
    "glucoseMgDl": 85,
    "leftPupil": "NORMAL",
    "rightPupil": "SLUGGISH",
    "medicalHistory": "고혈압",
    "allergies": "확인된 알레르기 없음",
    "medications": "혈압약",
    "isolationConcern": false
  }
}
```

- `supplementalAssessment` 전체가 없거나 `null`이면 추가 평가 기록을 만들지 않습니다.
- 객체를 보냈다면 여섯 평가 항목 중 하나 이상을 제공하고 `assessedAt`, `enteredAt`을 함께 보내야 합니다.
- 추가 평가가 없는 기존 요청 본문은 계속 성공해야 합니다.
- 생성 성공 응답에는 기존과 같이 환자 임상 원문을 반환하지 않습니다.
- 멱등성 요청 지문에는 정규화된 추가 평가를 포함합니다.
  - 같은 `Idempotency-Key`와 같은 본문은 기존 요청을 반환합니다.
  - 같은 키에서 추가 평가 하나라도 달라지면 `COMMON_005`로 거절합니다.

### 필드 규칙

| 필드 | 필수 조건 | 제약·의미 |
|---|---|---|
| `assessedAt` | 추가 평가 객체가 있으면 필수 | 실제로 추가 평가를 확인·측정한 임상 시각 |
| `enteredAt` | 추가 평가 객체가 있으면 필수 | 앱에서 기록을 입력한 시각 |
| `glucoseMgDl` | 선택 | 정수 0~1000, 단위 `mg/dL`; 미입력은 측정하지 않았다는 기록도 만들지 않음 |
| `leftPupil` | 동공 입력 시 필수 | `NORMAL`, `SLUGGISH`, `FIXED`, `UNASSESSABLE` |
| `rightPupil` | 동공 입력 시 필수 | 좌측과 같은 enum; 한쪽만 보내는 입력은 허용하지 않음 |
| `medicalHistory` | 선택 | 입력 전체(공백 포함) 1~120자, 저장 시 앞뒤 공백 제거 |
| `allergies` | 선택 | 입력 전체(공백 포함) 1~120자, 저장 시 앞뒤 공백 제거 |
| `medications` | 선택 | 입력 전체(공백 포함) 1~120자, 저장 시 앞뒤 공백 제거 |
| `isolationConcern` | 선택 | `true`는 우려 있음, `false`는 확인 결과 우려 없음, `null`·미입력은 기록 없음 |

- 선택 문자열을 보낼 때 빈 문자열이나 공백만 보낼 수 없습니다.
- `null`·미입력은 `정상`, `없음` 또는 `확인 불가`를 뜻하지 않고 해당 항목을 기록하지 않았다는 뜻입니다.
- 서버는 `serverReceivedAt`을 요청값이 아니라 서버 시각으로 기록합니다.
- 혈당 범위와 동공 enum은 현재 Flutter 개발 화면과 맞춘 전송 검증 범위이며 의료 정상 범위를 판정하지 않습니다.

### 조회 응답

- 구급대원 본인의 진행 중 이송 상세
  `GET /api/v1/transport-requests/{requestId}`에 `supplementalAssessment`를 추가합니다.
- 병원 제안 상세
  `GET /api/v1/hospitals/me/offers/{offerId}`에 `supplementalAssessment`를 추가합니다.
- 저장된 추가 평가가 없으면 응답 필드는 `null`입니다.
- 응답에는 입력값과 `assessedAt`, `enteredAt`, `serverReceivedAt`을 포함합니다.
- 병원 활성 목록과 종료 이력의 최소 카드에는 추가 평가 원문을 넣지 않습니다.
- 기존 임상 timeline, SSE payload와 감사 로그에는 이번 기능에서 추가 평가 원문을 넣지 않습니다.

## 정보 공개 범위

- 구급대원 상세 조회는 현재 계약대로 요청을 직접 생성한 활성 `PARAMEDIC` 계정만 허용합니다.
- 병원 상세 조회는 기존 제안 상세의 조직 범위를 유지하고, 새
  `supplementalAssessment` 필드는 기존 임상 timeline과 동일한 상태별 공개
  범위를 사용합니다.
  - 목적지 선택 전에는 요청을 전달받아 아직 수용 판단 권한이 있는 자기 병원
  - 목적지 선택 후에는 현재 목적지 병원
- 선택되지 않은 병원, 거절·철회 후 임상 접근이 끝난 병원과 다른 조직에는
  추가 평가를 반환하지 않습니다. 기존 제안 상세 자체가 이력 정책에 따라
  조회되는 경우에도 새 필드는 `null`입니다.
- 종료 이력에서는 기존 최소정보 계약을 유지하고 추가 평가 원문을 다시 공개하지 않습니다.
- `SUPER_ADMIN`은 추가 평가 생성·조회가 모두 금지됩니다.

## 기존 API 호환성

- 생성 요청의 `supplementalAssessment`는 선택 필드이므로 기존 Flutter 요청은 계속 성공합니다.
- 구급대원 상세과 병원 제안 상세에는 nullable 응답 필드만 추가하며 기존 필드를 삭제하거나 의미를 바꾸지 않습니다.
- 요청 생성 상태, 병원 자동 탐색, 목적지, 임상 갱신, 취소와 인계 계약은 변경하지 않습니다.
- 기존 데이터에는 추가 평가가 없으므로 조회 응답에서 `null`로 반환합니다.
