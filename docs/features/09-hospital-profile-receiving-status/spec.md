# 병원 내 정보·수신 상태 조회 요구사항

```text
Feature: hospital-profile-receiving-status
Owner: backend
Related Issue: NONE
Frontend Impact: REACT_HOSPITAL_ADMIN
Policy Decision Status: NONE
```

> 인증된 병원 공용 계정이 로그인 또는 화면 새로고침 뒤 자기 병원 정보와
> 서버에 저장된 실제 신규 요청 수신 상태를 조회하는 기능입니다. React 병원
> 웹이 브라우저에 마지막으로 저장한 값이 아니라 서버 상태를 기준으로 화면을
> 복구할 수 있게 합니다.

## 목적

- 병원 웹이 로그인·새로고침·다른 브라우저 접속 뒤에도 실제 수신 `ON/OFF` 상태를 표시합니다.
- 병원 계정 정보 화면에 조직명, 응급실 주소·연락처 등 가입 때 등록한 자기 병원 정보를 제공합니다.
- 조회 대상은 JWT로 인증된 자기 병원으로 고정하고 다른 병원 ID를 입력받지 않습니다.
- 기존 병원 가입, 로그인과 수신 상태 변경 API 계약을 유지합니다.

## 정책 기준

- 적용할 MVP 요구사항:
  - 병원은 응급실 단위 공용 계정 1개를 사용합니다.
  - 병원은 가입할 때 병원명, 응급실 주소·좌표·연락처를 등록합니다.
  - 가입 직후 수신 상태는 `OFF`이고, 병원 관계자가 확인 후 `ON`으로 변경합니다.
  - `ON`은 새 요청 후보 포함, `OFF`는 새 요청 후보 제외를 의미합니다.
  - `OFF`로 변경해도 이미 수락했거나 이동 중인 요청은 유지됩니다.
- 서버 DB의 병원 프로필을 현재 상태의 단일 기준으로 사용합니다.
- 조회 응답은 자기 병원 정보만 포함하며 환자 임상정보, 구급대원 연락처와 위치정보를 포함하지 않습니다.
- 조회는 상태를 변경하거나 감사 이벤트를 새로 만들지 않습니다.
- 기존 정책과 충돌: 없음

## 조회 응답 범위

`GET /api/v1/hospitals/me`는 다음 필드를 반환합니다.

| 구분 | 필드 | 설명 |
|---|---|---|
| 계정 | `accountId`, `loginId`, `role` | 현재 인증된 병원 공용 계정 |
| 조직 | `organizationId`, `organizationName` | 계정이 소속된 병원 조직 |
| 병원 | `hospitalId`, `address`, `latitude`, `longitude`, `contact` | 가입 때 등록한 자기 응급실 정보 |
| 수신 상태 | `receivingStatus`, `updatedAt` | 서버에 저장된 실제 `ON/OFF`와 병원 프로필 최종 변경 시각 |

- `role`은 `HOSPITAL_STAFF`입니다.
- `receivingStatus`는 `ON` 또는 `OFF`입니다.
- 비밀번호·해시, Access·Refresh Token, 가입 코드와 동의 내부 이력은 반환하지 않습니다.
- 이번 기능에서는 병원 정보 수정 API를 제공하지 않습니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 가입 직후 `OFF`인 병원 계정이 로그인해 대시보드에 진입 | 웹이 자기 병원 정보를 조회하고 서버의 `OFF`를 표시 |
| 2 | 병원 관계자가 수신 상태를 `ON`으로 변경한 뒤 화면을 새로고침 | 조회 API가 `ON`을 반환하고 브라우저 저장값 없이 같은 상태를 복구 |
| 3 | 같은 병원 계정으로 다른 브라우저에서 접속 | 첫 브라우저의 로컬 저장값과 무관하게 서버의 최신 병원 정보와 수신 상태를 표시 |
| 4 | 구급대원·슈퍼 관리자 또는 다른 조직 정보가 담긴 잘못된 인증으로 조회 | 병원 정보를 노출하지 않고 표준 인증·권한 오류 반환 |
| 5 | 같은 병원 계정의 두 화면이 같은 수신 상태를 동시에 저장 | 두 변경을 순서대로 처리하여 영속성 충돌을 외부 오류로 노출하지 않고 목표 상태 유지 |
| 6 | 한 화면은 `ON`, 다른 화면은 `OFF`를 거의 동시에 저장 | 두 변경을 순서대로 반영하고 마지막 완료 상태를 서버의 현재 상태로 유지; 불명확한 화면은 GET으로 복구 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 자기 병원 정보 조회 | `GET /api/v1/hospitals/me`에 Bearer JWT를 보내면 HTTP 200과 자기 계정·조직·응급실·수신 상태 반환 |
| 수신 상태 변경 후 재조회 | 기존 `PUT /api/v1/hospitals/me/receiving-status` 성공 뒤 `GET /api/v1/hospitals/me`가 변경된 상태 반환 |
| 웹 로그인·새로고침 복구 | React 병원 웹은 조회 응답의 `receivingStatus`를 서버 기준 화면 상태로 사용 |
| 조회 실패 | 기존 화면에 임의의 `ON/OFF`를 확정 표시하지 않고 인증 복구 또는 오류 상태 처리 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| `HOSPITAL_STAFF` | 자기 병원 정보와 현재 수신 상태 조회 | JWT 계정과 조직에 연결된 병원 프로필 한 건만 |
| `PARAMEDIC` | 없음 | 병원 프로필 조회 금지 |
| `SUPER_ADMIN` | 없음 | 이 API를 통한 병원 공용 계정 프로필 조회 금지 |
| 미인증 사용자 | 없음 | 인증 필요 |

- 서버는 JWT의 계정 ID·조직 ID·역할을 현재 DB의 활성 계정·조직과 다시 대조합니다.
- 경로나 Query, 요청 본문으로 병원·계정·조직 ID를 입력받지 않습니다.
- 병원 프로필의 조직과 인증 조직이 다르면 정보를 반환하지 않습니다.

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 인증정보가 없음 | `AUTH_001` | 401 |
| Access Token이 유효하지 않거나 계정이 비활성 | `AUTH_002` | 401 |
| 병원 관계자가 아닌 역할이 조회 | `AUTH_003` | 403 |
| 계정·JWT·조직 또는 프로필 조직이 일치하지 않음 | `COMMON_004` | 403 |
| 인증 계정에 연결된 병원 프로필이 없음 | `HOSPITAL_001` | 404 |

모든 오류는 기존 공통 오류 응답과 `X-Trace-Id` 계약을 유지합니다.
