# MVP 병원 탐색 지속 계약 요구사항

```text
Feature: mvp-hospital-search-continuation
Owner: backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: RESOLVED
```

> MVP 요구사항 4.13, 10.3과 기능 04의 확정 정책을 현재 구현에 반영합니다.
> 최소 한 병원이 최종적으로 수락한다는 MVP 가정 안에서 동작합니다.

## 목적

- 병원이 응답하지 않았다는 이유로 제안을 자동 종료하지 않습니다.
- 최대 반경 도달을 별도 이송 실패 상태로 만들지 않습니다.
- 후보 소진 뒤 전체 재전송·전화 연결 동작을 공개하지 않습니다.
- 첫 수락 전 반경 확대와 병원의 명시적 수락·거절은 유지합니다.

## 정책 기준

- 최초 반경 10km, 최소 후보 3곳, 10km 단위 확대, 최대 100km를 유지합니다.
- 최초 후보가 3곳 미만이면 3곳 이상이 처음 발견되는 반경까지 즉시 확대합니다.
- 첫 전송 이후 수락이 없으면 60초마다 반경을 확대합니다.
- 첫 수락이 발생하면 자동 확대를 중단합니다.
- 병원이 수락·거절하지 않으면 제안은 계속 `PENDING`입니다.
- 최대 100km에 도달하면 추가 확대 예약만 종료합니다.
- 최대 반경에서도 이송 요청과 탐색 회차는 `SEARCHING`으로 유지합니다.
- 적격 병원이 없거나 모든 병원이 거절한 경우에도 `NO_RESPONSE`나
  `CANDIDATES_EXHAUSTED`를 새로 만들지 않습니다.
- MVP는 최소 한 병원이 최종 수락한다고 가정하므로 별도 실패 복구 UI를 제공하지 않습니다.
- 구급대원이 누르는 전체 재전송 API와 병원 전화 연결 기능을 제공하지 않습니다.
- 같은 이송 요청과 병원에는 제안 카드 하나만 유지합니다.
- 목적지 병원의 긴급 철회 후 재검색 상세 정책은 기능 05의 후속 정렬 범위로 남깁니다.

기존 DB의 `NO_RESPONSE`, `CANDIDATES_EXHAUSTED`, `EXHAUSTED`, `MANUAL_RETRY`
값과 관련 enum은 과거 데이터 읽기와 Flyway 호환을 위해 삭제하지 않습니다. 새 요청
흐름에서는 생성하지 않습니다.

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 10km 1곳, 20km 2곳, 30km 4곳 | 30km의 적격 병원 4곳에 최초 요청 |
| 2 | 60초 동안 수락 없음 | 다음 반경의 신규 병원에만 요청, 기존 `PENDING` 유지 |
| 3 | 100km 도달 뒤 C병원이 계속 미응답 | C는 `PENDING`, 요청·회차는 `SEARCHING`, 다음 확대 시각은 없음 |
| 4 | A병원이 거절하고 B병원이 수락 | A는 `REJECTED`, B는 `ACCEPTED`, 자동 확대 중단 |
| 5 | 사용자가 기존 전체 재전송 경로를 호출 | 공개 API가 없으므로 재전송 회차가 생성되지 않음 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 이송 요청 생성 | 현재 위치 기준 최초 탐색과 병원별 제안 생성 |
| 검색 현황 조회 | `GET /api/v1/transport-requests/{requestId}/hospital-search` |
| 최대 반경 대기 | `status: SEARCHING`, `currentAttempt.status: SEARCHING`, `nextExpansionAt: null` |
| 병원 응답 대기 | 제안 `status: PENDING`, `closedAt: null` 유지 |
| 병원 수락·거절 | 기존 병원 응답 API와 멱등성 계약 유지 |
| 전체 재전송 | `POST .../{requestId}/dispatch-attempts`를 제공하지 않음 |

검색 현황 응답의 `exhaustionReason` 필드는 기존 JSON 호환을 위해 남기지만 새 요청에서는
항상 `null`입니다. 프론트는 이를 상태 분기에 사용하지 않습니다.

## 기능 내 결정 사항

| 쟁점 | 결정 | 이유·영향 |
|---|---|---|
| 최대 반경 이후 내부 상태 | `SEARCHING`, `nextExpansionAt: null` | 실패 상태 없이 현재 탐색과 응답 대기를 유지 |

| 전체 재전송 API | 제거 | MVP 제외 기능을 프론트 계약에서도 제거 |
