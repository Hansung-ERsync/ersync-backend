# 조직 가입 및 사용자 인증 요구사항

```text
Feature: account-onboarding-auth
Owner: backend
Related Issue: NONE
Frontend Impact: BOTH
Policy Decision Status: NONE
```

> 슈퍼 관리자가 조직과 가입 코드를 관리하고, 병원 관계자와 구급대원이
> 각 클라이언트에서 가입·로그인하여 역할과 조직 범위 안에서 서비스를
> 사용할 수 있게 하는 하나의 사용자 흐름입니다.

## 목적

- 슈퍼 관리자가 병원·구급대 조직과 조직·역할별 일회용 가입 코드를 관리합니다.
- 병원 관계자는 React 웹에서 병원 공용 계정을 만들고 응급실 정보를 등록합니다.
- 구급대원은 Flutter 앱에서 소속 구급대 조직의 개인 계정을 만듭니다.
- 가입한 사용자는 로그인하여 서버가 검증한 역할과 조직 권한으로 보호 API를 사용합니다.

## 정책 기준

- 적용할 MVP 요구사항:
  - 슈퍼 관리자는 병원·구급대 조직을 등록하고 가입 코드를 발급·조회·조기 만료합니다.
  - 가입 코드는 조직과 역할에 묶인 일회용 코드이며 3일, 7일 또는 직접 설정한 기간을 사용합니다.
  - 가입 코드 원문은 발급 응답에서 한 번만 표시하고 서버에는 암호학적 해시만 저장합니다.
  - 가입 코드 상태는 `AVAILABLE`, `USED`, `EXPIRED`, `REVOKED`이며 발급·사용·만료·폐기를 감사 기록으로 남깁니다.
  - 구급대원은 구급대 조직에 소속된 개인 계정을 사용합니다.
  - 병원은 병원별 응급실 공용 계정 하나를 사용합니다.
  - 병원 가입 시 응급실 주소, 확인된 위도·경도와 연락처를 등록합니다.
  - 병원의 최초 수신 상태는 `OFF`이며 `ON`일 때만 신규 요청 후보가 됩니다.
  - 병원 조직은 `HOSPITAL_STAFF`, 구급대 조직은 `PARAMEDIC` 가입 코드만 사용하며 `SUPER_ADMIN` 가입 코드는 발급하지 않습니다.
  - 비밀번호와 가입 코드는 단방향 해시로 저장하고 원문을 로그에 남기지 않습니다.
  - 슈퍼 관리자는 환자 임상정보와 위치정보를 조회할 수 없습니다.
- 기존 정책과 충돌: 없음

## 시나리오

| # | 상황 | 기대 결과 |
|---:|---|---|
| 1 | 슈퍼 관리자가 병원 또는 구급대 조직을 등록하고 역할과 유효기간을 지정해 가입 코드를 발급함 | 가입 코드 원문을 한 번만 반환하고, 이후 조회에는 원문·해시 없이 상태와 메타데이터만 표시함 |
| 2 | 병원 관계자가 유효한 병원 가입 코드와 응급실 정보를 React 웹에서 제출함 | 해당 병원에 공용 계정 하나와 병원 프로필이 생성되고 코드는 `USED`, 수신 상태는 `OFF`가 됨 |
| 3 | 구급대원이 유효한 구급대 가입 코드를 Flutter 앱에서 제출함 | 코드에 지정된 구급대 조직과 `PARAMEDIC` 역할에 연결된 개인 계정이 생성되고 코드는 `USED`가 됨 |
| 4 | 등록된 사용자가 올바른 자격정보로 로그인함 | 이후 보호 API에서 사용할 인증정보와 자신의 계정·역할·조직 범위를 확인할 수 있음 |
| 5 | 병원 공용 계정이 응급실 수신 상태를 `ON` 또는 `OFF`로 변경함 | 자기 병원의 상태만 변경되며 `OFF`는 신규 요청 후보 제외에만 사용되고 기존 요청을 철회하지 않음 |

## 외부 동작

| 행위 | 요청·응답 또는 상태 변화 |
|---|---|
| 조직 등록·조회 | 슈퍼 관리자가 조직명과 `HOSPITAL` 또는 `EMS_UNIT` 유형을 등록하고 목록을 조회함 |
| 가입 코드 발급 | 슈퍼 관리자가 조직, 대상 역할, 3일·7일·직접 설정 만료를 지정하며 성공 응답에서만 원문 코드를 확인함 |
| 가입 코드 조회·폐기 | 슈퍼 관리자가 원문·해시가 제외된 코드 메타데이터와 상태를 조회하고 사용 전 코드를 `REVOKED`로 변경함 |
| 병원 회원가입 | 병원 코드, 조직명 확인, 공용 로그인 ID·비밀번호, 응급실 주소·위치·연락처를 제출함 |
| 구급대원 회원가입 | 구급대원 코드와 개인 로그인 ID·비밀번호를 제출하며 역할과 조직은 코드에서 결정됨 |
| 로그인 | 활성 계정이 로그인 ID와 비밀번호를 제출하고 보호 API에 사용할 인증정보를 받음 |
| 응급실 수신 상태 변경 | 병원 공용 계정이 자기 병원의 상태만 `ON` 또는 `OFF`로 변경함 |

## 권한

| 역할 | 허용 작업 | 접근 범위 |
|---|---|---|
| 미인증 사용자 | 가입 코드로 회원가입, 로그인 | 제출한 가입 코드와 자격정보의 검증 결과만 확인 |
| `SUPER_ADMIN` | 조직 등록·조회, 가입 코드 발급·조회·폐기 | 조직과 가입 코드 관리정보만 접근하며 환자·위치정보 접근 불가 |
| `PARAMEDIC` | 로그인 후 보호 기능 사용 | 자신의 계정과 소속 구급대 조직 범위로만 접근 |
| `HOSPITAL_STAFF` | 로그인 후 보호 기능 사용, 응급실 수신 상태 변경 | 자신의 계정과 소속 병원 프로필 범위로만 접근 |

## 오류

| 조건 | 기대 결과 또는 오류 코드 | HTTP |
|---|---|---:|
| 요청 필드 형식 또는 좌표가 올바르지 않음 | `COMMON_001` | 400 |
| 로그인 ID가 이미 사용 중임 | `USER_003` | 409 |
| 가입 코드를 찾을 수 없거나 검증할 수 없음 | `INVITATION_001` | 400 |
| 가입 코드가 만료됨 | `INVITATION_002` | 409 |
| 가입 코드가 이미 사용됨 | `INVITATION_003` | 409 |
| 가입 코드가 폐기됨 | `INVITATION_004` | 409 |
| 사용 전 상태가 아닌 가입 코드를 폐기함 | `INVITATION_005` | 409 |
| 로그인 ID 또는 비밀번호가 올바르지 않음 | `AUTH_004` | 401 |
| Refresh Token이 유효하지 않거나 재사용됨 | `AUTH_005` | 401 |
| 비활성 계정으로 접근함 | `USER_002` | 403 |
| 역할이나 다른 조직의 정보에 접근함 | `AUTH_003` 또는 `COMMON_004` | 403 |
| 병원 조직에 이미 공용 계정이 존재함 | `USER_004` | 409 |

> 신규 오류 코드의 공개 메시지와 사용 경로는 `implementation.md` 및 테스트를
> 기준으로 함께 추가합니다.
