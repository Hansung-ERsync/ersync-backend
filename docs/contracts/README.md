# 프론트엔드 연동 계약

백엔드 기능이 프론트엔드에 미치는 변경을 기능별 한 문서로 전달합니다.
프론트엔드 에이전트는 공통·프론트엔드 컨텍스트 다음에 해당 계약을 읽습니다.

## 구조

```text
docs/contracts/{기능 번호}-{기능명}.md
```

기능 하나에 프론트엔드 계약 문서 하나만 만듭니다. 도메인 폴더를 중첩하지
않습니다.

## 생성 기준

다음 중 하나라도 변경되면 계약 문서를 만듭니다.

- API Method, Path, 요청 또는 응답
- 인증, 역할 또는 조직 접근 범위
- 상태, Enum 또는 화면 분기 조건
- 오류 코드와 프론트엔드 처리
- 실시간 이벤트와 재조회 조건

프론트엔드 영향이 없으면 계약 문서를 만들지 않고 기능 `review.md`에
`Frontend Impact: NONE`을 기록합니다.

## 생성 시점

```text
기능 구현
→ 로컬 테스트
→ review.md 갱신
→ 실제 코드 기준 계약 작성
→ PR 생성
→ main 병합
```

계약은 구현과 검증을 마친 실제 코드 기준으로만 작성합니다. 계약 파일이 PR에
포함되어 있으면 프론트엔드 전달이 가능한 확정 계약으로 취급합니다. 실제 dev
API는 `main` 병합과 배포 성공 후 사용할 수 있습니다.

## 기준 관계

- 제품 정책: `docs/project/mvp-requirements.md`
- 기능 범위·정책: 팀 검토와 구현 전 확인을 마친 `spec.md`
- 정확한 기술 동작: 백엔드 코드와 테스트
- 프론트 연동 방법: 해당 `contracts/*.md`

별도의 수동 API 계약 문서는 만들지 않습니다. API 필드, 권한, 오류와 이벤트를
이 계약에 함께 기록합니다. OpenAPI를 도입하면 정확한 스키마는 OpenAPI를
기준으로 하고 이 문서는 변경 요약과 프론트 처리 방법을 설명합니다.
